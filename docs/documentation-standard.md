# 编写与维护文档

> 状态：当前。

一页解决一个问题。操作指南给出前置条件、步骤和成功标志；设计文档说明组件各自负责什么，以及由什么约束决定设计。把可能收费、泄密、扩大授权或丢失数据的后果写在对应动作旁。

## 放在哪里

| 位置 | 内容 |
| --- | --- |
| 中英文 README | 产品概览、快速入口、许可证；两种语言覆盖相同功能 |
| `docs/user/` | 安装、调用、配置、排障与恢复 |
| `docs/development/` | 实现、设计取舍、验证与交付 |
| `docs/reference/` | 外部协议及网关支持范围；标明官方来源和实际核对日期 |
| `docs/openapi/` | Console API 的机器可读契约 |
| `docs/archive/` | 仅供追溯的历史方案 |

用相对链接把新页面加入对应索引。已有权威说明时直接链接；移动页面或改标题时全仓更新路径、锚点和发行打包清单。保留现有页面语言。

## 变更同步矩阵

| 改动 | 同步内容 |
| --- | --- |
| 公共 API、Header 或顶层字段 | [机器策略](reference/request-allowlists.json)、[协议参考](reference/README.md)、调用指南和测试 |
| Console API | [OpenAPI](openapi/console-v1.yaml)、生成的 TypeScript 类型、调用方和契约测试 |
| 进程配置 | `src/runtime_config/`、根目录与 Compose 两份配置模板、用户配置指南 |
| 存储、结算或恢复 | migration、双后端测试、持久化契约和升级/恢复指南 |
| 转发与插件 | 对应操作、宿主与插件职责、确定性和真实上游测试入口 |
| Console UI | 前端指南、操作路径、组件或浏览器测试 |
| 部署与发行 | 部署指南、README、打包脚本与随附许可证 |

## 格式与检查

使用小写 kebab-case 文件名，每页一个一级标题。根 README、用户、开发和归档文档在前 12 行以 `> 状态：` 或 `> Status:` 标明当前、提案或历史状态；外部参考标明类型、最近核对日期和权威来源。只在重新核查外部来源后更新日期。

```bash
git diff --check
python3 scripts/check-docs.py
```

脚本检查本地链接的目标文件、一级标题和元数据。另行核对改过的锚点、示例命令与实现；示例凭据使用占位符。
