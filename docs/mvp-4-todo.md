# MVP 4 后端任务清单

目标：补齐可运营的控制面，并在既有不可变快照、异步日志和单次代理语义之上，逐步引入模型目录、定价、用量与结算能力。

## 执行约定

- 每个阶段开始前，将阶段目标和可验证子任务写入本文件；只有全部子任务、测试和提交完成后才开始下一阶段。
- 控制面写入必须继续通过 `ControlPlaneCoordinator`：同一串行化事务内完成写入、完整候选快照编译、allowlist 审计和提交后即时发布。
- 任何用量或计费实现不得缓冲普通流式响应、不得改变“单次上游尝试”约束，并必须保持 Chat Completions 与 Responses 的独立解析路径。
- 在转发路径发生改变的阶段完成前，除标准检查外必须运行 `./scripts/run-real-upstream-smoke.sh`；不得输出或提交其凭据。

## 阶段 1：用户与模型控制面

阶段目标：除第一个受控 provisioning 的 bootstrap actor 外，消除新部署依赖手工 SQL 创建用户和模型的缺口，使管理员可通过本地管理监听器完整管理 API Key 的归属用户和 model rule 的计费模型；余额仍只读，不在本阶段引入结算。

阶段状态：已完成

### 阶段 1 执行任务

- [x] 1.1 定义用户、模型的受控管理输入与普通响应 DTO；用户余额只读，模型原始元数据仅接受 JSON object。
- [x] 1.2 扩展 `AdminLists`、仓储查询和管理路由，提供 users/models 的列表、读取、创建和 ETag 全量更新接口。
- [x] 1.3 将用户、模型写入纳入现有 `AdminMutation`、串行化事务、完整候选快照校验和提交后即时发布。
- [x] 1.4 对用户状态变化和模型启停保持引用完整性：停用后影响运行时 Key/规则；若使候选快照无效，整笔写入与审计均回滚。
- [x] 1.5 为用户和模型审计使用明确 allowlist；不得引入余额调整、请求正文或凭据泄露。
- [x] 1.6 添加 PostgreSQL 集成测试，覆盖创建、ETag 冲突、即时快照效果、模型停用回滚及审计记录。
- [x] 1.7 更新运行说明，移除“必须手工写入用户和模型”的过时描述；运行格式化、lint、测试并提交阶段成果。

## 阶段 2：模型目录同步与价格管理

阶段目标：由管理员显式触发、可审计地同步并选择模型目录数据，更新当前价格而不修改既有请求日志的价格快照。

阶段状态：已完成

- [x] 2.1 定义外部目录客户端、受限响应模型和同步失败策略。
- [x] 2.2 实现管理员触发的预览、选择与 upsert 流程，并限制原始元数据大小。
- [x] 2.3 校验币种、计价单位、四类单价与生效时间；记录脱敏审计并立即发布候选快照。
- [x] 2.4 添加本地 HTTP 与 PostgreSQL 集成测试；明确暂不自动定时同步。

## 阶段 3：格式独立的用量采集与价格快照

阶段目标：从两种 API 格式的非流式响应与 SSE 事件中增量提取 usage，将 token、价格快照和成本写入终态请求日志，但暂不变更余额或额度。

- [ ] 3.1 为 Chat Completions、Responses 分别定义 usage 提取器和不可识别 usage 的安全降级行为。
- [ ] 3.2 在不缓冲普通流的前提下捕获非流式和 SSE usage；保持变换、取消和空闲超时语义。
- [ ] 3.3 在选路时绑定计费模型的价格快照，计算并持久化成本与可选 TPS。
- [ ] 3.4 扩展日志幂等比较和集成测试，覆盖缺失 usage、流式 usage、转换失败和取消。

## 阶段 4：幂等结算与额度策略

阶段目标：在已持久化的价格快照和 usage 基础上，以 `billed_at` 为唯一结算权原子更新 API Key 已用额度与用户余额；硬额度预留另行设计，不与软预检查混淆。

- [ ] 4.1 定义结算资格、余额不足和失败重试策略。
- [ ] 4.2 在一个事务中以条件更新取得 `billed_at` 唯一结算权，并更新余额及 `quota_used_amount`。
- [ ] 4.3 处理 worker 重投、崩溃恢复和并发结算的幂等性。
- [ ] 4.4 添加结算与对账集成测试，并更新准入语义和运维文档。

## 暂不纳入 MVP 4

- 主动健康检查、自动禁用策略和跨实例健康状态。
- 多实例限流/配置发布协调。
- 通用请求重试和跨渠道自动重试。
- 独立财务账本、充值、退款与多币种兑换。
