# MVP 4 后端任务清单

目标：补齐可运营的控制面，并在既有不可变快照、异步日志和单次代理语义之上，逐步引入模型目录、定价、用量与结算能力。

## 执行约定

- 每个阶段开始前，将阶段目标和可验证子任务写入本文件；只有全部子任务、测试和提交完成后才开始下一阶段。
- 控制面写入必须继续通过 `ControlPlaneCoordinator`：同一串行化事务内完成写入、完整候选快照编译、allowlist 审计和提交后即时发布。
- 任何用量或计费实现不得缓冲普通流式响应、不得改变“单次上游尝试”约束，并必须保持 Chat Completions 与 Responses 的独立解析路径。
- 在转发路径发生改变的阶段完成前，除标准检查外必须运行 `./scripts/run-real-upstream-smoke.sh`；不得输出或提交其凭据。

## 阶段 1：用户与模型控制面

阶段目标：除第一个受控 provisioning 的 bootstrap actor 外，消除新部署依赖手工 SQL 创建用户和模型的缺口，使管理员可通过本地管理监听器完整管理 API Key 的归属用户和 model rule 的计费模型；余额仍只读，不在本阶段引入结算。

阶段状态：已完成

- [x] 1.2 扩展 `AdminLists`、仓储查询和管理路由，提供 users/models 的列表、读取、创建和 ETag 全量更新接口。
- [x] 1.3 将用户、模型写入纳入现有 `AdminMutation`、串行化事务、完整候选快照校验和提交后即时发布。
- [x] 1.4 对用户状态变化和模型启停保持引用完整性：停用后影响运行时 Key/规则；若使候选快照无效，整笔写入与审计均回滚。
- [x] 1.5 为用户和模型审计使用明确 allowlist；不得引入余额调整、请求正文或凭据泄露。

## 阶段 2：模型目录同步与价格管理

阶段目标：由管理员显式触发、可审计地同步内部 `models` 价格表。默认同步只更新已由 models.dev 导入的本地模型价格；新增模型必须先由管理员在预览中显式选择并导入，且不修改既有请求日志的价格快照。

阶段状态：已完成（同步语义调整）

- [x] 2.1 保留受限外部目录客户端和失败策略，识别本地已导入模型的 provider/model 来源。
- [x] 2.2 将预览区分为现有价格更新与可手动导入模型，保持原始元数据大小限制。
- [x] 2.3 将默认同步改为只更新已存在模型的当前价格、价格生效时间和同步元数据；缺失/不可用远端价格不得覆盖本地价格。
- [x] 2.4 将新增改为显式导入接口，拒绝已有本地 `source_model_id`，并在同一事务中审计、校验和发布。
- [x] 2.5 添加本地 HTTP 与 PostgreSQL 集成测试，覆盖默认更新不新增、手动导入、远端缺失价格和审计；明确暂不自动定时同步。

## 阶段 3：格式独立的用量采集与价格快照

阶段目标：从两种 API 格式的非流式响应与 SSE 事件中增量提取 usage，将 token、价格快照和成本写入终态请求日志，但暂不变更余额或额度。

阶段状态：已完成

- [x] 3.1 为 Chat Completions、Responses 分别定义 usage 提取器和不可识别 usage 的安全降级行为。
- [x] 3.2 在不缓冲普通流的前提下捕获非流式和 SSE usage；保持变换、取消和空闲超时语义。
- [x] 3.3 在选路时绑定计费模型的价格快照，计算并持久化成本与可选 TPS。
- [x] 3.4 扩展日志幂等比较和集成测试，覆盖缺失 usage、流式 usage、转换失败和取消。

## 阶段 4：幂等结算与额度策略

阶段目标：在已持久化的价格快照和 usage 基础上，以 `billed_at` 为唯一结算权原子更新 API Key 已用额度与用户余额；硬额度预留另行设计，不与软预检查混淆。

阶段状态：已完成

### 阶段 4 执行策略

- 仅对 `cost_amount IS NOT NULL`、`billed_at IS NULL`、价格快照完整且 API Key 仍归属该用户的终态日志结算；系统价格和费用固定为 USD。有 usage 的 `failed` / `cancelled` 请求也可结算，`cost_amount = 0` 仍写入 `billed_at`。
- 本阶段不实现余额或额度预留，也不以余额不足阻止结算：余额可扣至负数，`quota_used_amount` 可超过 `quota_limit_amount`；下一次使用由已结算软额度预检查拒绝。
- 插入日志后立即尝试结算；临时数据库失败会保留 `billed_at IS NULL`，由 worker 启动时和周期性扫描重试。归属不匹配不写入 `billed_at`，等待管理员修正数据后再进入扫描范围。

- [x] 4.1 定义结算资格、余额不足和失败重试策略。
- [x] 4.2 在一个事务中以条件更新取得 `billed_at` 唯一结算权，并更新余额及 `quota_used_amount`。
- [x] 4.3 处理 worker 重投、崩溃恢复和并发结算的幂等性。
- [x] 4.4 添加结算与对账集成测试，并更新准入语义和运维文档。

## 暂不纳入 MVP 4

- 主动健康检查、自动禁用策略和跨实例健康状态。
- 多实例限流/配置发布协调。
- 通用请求重试和跨渠道自动重试。
- 独立财务账本、充值、退款与多币种兑换。
