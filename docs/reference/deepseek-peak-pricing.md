# DeepSeek 峰谷定价参考

> 类型：外部价格来源与网关计费预设说明。
>
> 最近核对：2026-08-17。以下价格关系是该日期的观察，不是实时报价。
>
> 权威来源：[DeepSeek 模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

## 使用预设

在 Console 的模型定价子页选择 DeepSeek 预设，检查基础单价、星期和 UTC 窗口，再显式保存。
预设只填表，不向 DeepSeek 抓取价格，也不自动改变已有模型计费。

核对时的配置思路为：基础价填空闲时段价，高峰窗口统一乘 `2`。

| 开始星期 | UTC 半开窗口 | 倍率 |
| --- | --- | --- |
| 周一至周日 | `[01:00, 04:00)` | `2` |
| 周一至周日 | `[06:00, 10:00)` | `2` |
| 其余时间 | 不配置额外窗口 | 基础价 |

**上线前重新核对官方价格页**。即使 HTTP 请求和 usage 正常，也不能证明本地价格与供应商账单一致。

## 外部接口关键语义

2026-08-17 的来源记录为空闲单价是高峰的一半，上表两个 UTC 窗口为高峰；
相同二倍关系适用于缓存命中输入、未命中输入与输出。这不是网关承诺 DeepSeek 永久采用该规则。

## ai-gateway 兼容行为

`advanced_billing.time_multipliers` 是通用每周 UTC 倍率规则，不识别或硬编码 DeepSeek 品牌。
窗口按逻辑请求开始时间选择，开始包含、结束不包含；可选开始星期，旧配置省略时按每天。
开始晚于结束表示跨午夜，同模型窗口不能重叠。

预设选择全部星期；管理员仍负责基础价和适用日期。models.dev 价格同步不创建、覆盖或清除
管理员维护的时段倍率，因此同步基础价后也要检查组合后的实际单价。

## 差异与限制

- 只支持每周 UTC 循环，不支持 IANA 时区、夏令时、节假日或一次性临时调价。
- 一个窗口统一影响输入、缓存输入、缓存写入和输出，不能分别给四种计价项不同倍率。
- 预设不是供应商账单核对器，也不自动随外部涨价/降价更新。

## 维护检查项

官方规则变化时，先核对窗口、倍率和适用计价项，再同步 Console 预设、表单测试和
[用户计费说明](../user/operations.md)。只在实际核对来源后更新本页日期，
保留“外部报价”与“网关通用规则”的分界。
