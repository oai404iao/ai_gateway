## 外部协议关键语义

截至 2026-08-06，MCP 最新稳定协议版本为 `2026-07-28`。该版本把远程
Streamable HTTP 改为无协议 Session 的请求模型：

- 不再使用 `initialize` / `notifications/initialized`；
- 客户端通过 `server/discover` 获取版本、能力和服务元数据；
- 每个请求独立携带协议版本、客户端能力/实现信息、方法、名称和参数元数据；
- 不再使用 `Mcp-Session-Id`；
- 不再提供独立 `GET` SSE 流、`DELETE` Session 终止或
  `Last-Event-ID` Session 恢复；
- 普通 JSON 响应仍可用于不需要服务器推送的工具服务。

这意味着“无状态 MCP”至少要满足：

1. 任一请求可由任一 Gateway 实例处理；
2. handler 不依赖上一次请求留下的进程内对象；
3. 需要跨调用继续使用的上下文必须作为普通、显式的工具参数或返回值交还客户端；
4. 若以后启用 Tasks、订阅或其他持久能力，其状态必须放在独立持久化层，而不能恢复协议
   Session。

### Streamable HTTP 请求

`2026-07-28` 的 HTTP 请求除 JSON-RPC body 外，还要求标准 MCP Header。关键 Header 包括：

- `MCP-Protocol-Version`
- `Mcp-Method`
- `Mcp-Name`
- 由工具 Schema 中 `x-mcp-header` 声明的 `Mcp-Param-*`

服务端必须验证 `Host` 和 `Origin`，避免 DNS rebinding。生产部署位于 TLS 反向代理之后时，
允许的公开 host/origin 必须显式配置，不能默认信任任意 `X-Forwarded-*`。

### `2025-11-25` 兼容语义

旧协议使用 `initialize` / `notifications/initialized` 生命周期。Streamable HTTP 服务端可以在
初始化响应中签发 `Mcp-Session-Id`；一旦签发，客户端必须在后续请求中携带该 ID。服务端可以用
请求级 SSE 返回响应，也可以提供独立 GET SSE，并可接受 DELETE 结束 Session。

这类 Session 是 transport/lifecycle 状态，不应被用来隐式保存 Search 历史、最近图片或用户
提示词。进程内实现重启后会失效，多实例部署需要粘性路由；跨实例恢复需要独立 Session store。

### Tools

工具服务至少使用：

- `tools/list`
- `tools/call`

工具定义包括名称、描述、`inputSchema`，并可提供 `outputSchema`。工具调用结果可以同时包含：

- `content`：文本、图片、音频、resource link 或嵌入资源；
- `structuredContent`：与 `outputSchema` 对应的结构化 JSON；
- `isError`：表示工具执行失败，而不是 JSON-RPC 协议失败；
- `_meta`：客户端或实现专用的附加元数据。

若同时返回 `structuredContent` 与文本兼容内容，不应无必要地重复大型图片或音频载荷。

### Authorization

MCP Authorization 规范对受保护的 HTTP 服务推荐 OAuth 2.1、Protected Resource Metadata、
资源 audience 绑定和最小 scope。规范使用 `SHOULD` 而非所有场景强制 `MUST`，但简单的预共享
API Key Bearer 模式并不等同于完整 MCP OAuth profile。

因此，`ai-gateway` 第一阶段若复用现有
`Authorization: Bearer <gateway-api-key>`，必须明确把它记录为 Gateway 专用兼容鉴权：

- API Key 只对当前 Gateway resource 生效；
- 不向上游转发；
- 仍按 API format、route、RPM、并发和额度执行现有授权；
- 后续如需要通用 MCP OAuth 客户端自动发现，应在不改变工具契约的前提下增加标准 OAuth
  resource server 层。

### Rust SDK

官方 Rust SDK `rmcp` 3.x 支持 MCP `2026-07-28`。截至核对日期，最新稳定版为
`3.1.1`，最低 Rust 版本为 1.88，低于本项目 MSRV 1.92。其 Streamable HTTP server 支持：

- 无 Session handler；
- JSON 响应；
- 可选旧协议兼容；
- 严格的现代无状态协议元数据校验；
- Axum router 集成。

## ai-gateway 采用的范围

实施记录见 [MCP 服务架构与实施记录](../development/mcp-services.md)。当前 Search 与 Images
generation/edit MCP 采用：

- Streamable HTTP；
- `server/discover`；
- `tools/list`；
- `tools/call`；
- JSON 响应；
- 默认无 `Mcp-Session-Id` 和独立 SSE GET；
- 可选完整 `2025-11-25` Session/SSE 兼容；
- 无 prompts、resources、sampling、subscriptions 或 Tasks。

默认以 `2026-07-28` 为规范版本。管理员可以显式开启完整 `2025-11-25` 兼容；该模式使用
进程内 Session、`Mcp-Session-Id`、GET SSE 和 DELETE，同时继续让 `2026-07-28` 请求保持严格
无状态。旧 Session 不保存工具业务历史，修改全局 MCP transport 设置或关闭进程会终止 Session。

## 与外部协议的差异

- 首期 API Key Bearer 是 Gateway 专用 profile，不是完整 MCP OAuth 2.1 实现。
- Search 与 Images generation/edit 工具由静态编译的内置 registry 提供；两者都不接受管理员上传
  任意代码、Schema、JavaScript、WASM 或动态插件。
- Images generation/edit 同步返回单张 PNG/base64 MCP `ImageContent`；长任务 Tasks
  扩展留待后续阶段。Edit 只接受最多五个显式 PNG/JPEG/WebP data URL，不获取远程资源。
- Search 跨调用上下文和 Images edit 输入都必须由客户端显式回传，服务端不保留会话历史。
- `2025-11-25` Session 当前仅在单个 Gateway 进程内有效；未实现 PostgreSQL/Redis Session store
  或跨实例 SSE event replay。

## 维护检查项

升级 MCP 或 `rmcp` 前至少检查：

1. 最新稳定协议版本和 release notes；
2. Streamable HTTP Header、发现流程和版本协商；
3. Tools result、structured content、图片 content 和错误语义；
4. Authorization resource/audience 要求；
5. `rmcp` MSRV、Axum/Hyper/Tokio 依赖兼容性；
6. 官方 conformance tests；
7. 旧协议 initialize、Session ID、GET/DELETE、空闲回收和多实例粘性路由；
8. 本项目反向代理、Origin、body limit 和关闭排空行为。
