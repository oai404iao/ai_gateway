# 新账本使用独立基线

> 状态：已采纳。

**选择。** PostgreSQL 与 SQLite 分别从一份当前 schema 初始化；请求日志只使用一种终态编码。新制品不接管历史迁移链、旧数据库入口或旧 spool。两后端的基线都编号为 1，不意味着格式可互换，或旧版本 1 的数据库可重开。

**取舍。** 继续原地升级，需要维护旧渠道和操作映射、旧事件缺字段时的推断，以及账本切换时的费用与回执校验。只恢复一部分旧记录比明确拒绝更危险：完整终态可能没有入账，已结算记录也可能再次被认领。当前设计在空库中建立唯一的事实格式，凭证归属随事实保存，无需靠旧绑定补全；代价是不能将旧配置、账户或账单带入新实例。

**操作后果。** 切换不是迁移：在旧系统停止派发并核对剩余费用，停写后保留数据库、完整 spool 和旧制品。使用新库与全新 spool 启动新系统；不能靠清空旧迁移记录、重置 checkpoint 或复制 journal 来转换。当前格式的崩溃恢复及同基线成对备份还原仍受支持。回退只能由匹配版本恢复其配套备份，并核对恢复点以后的上游使用，见[升级与回滚](../user/upgrades.md)。
