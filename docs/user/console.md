# 使用 Console 与管理 API

> 状态：当前。

浏览器通过 HTTPS 访问独立的 Console 监听器。第一次运行请先[创建管理员并启用界面](quickstart.md)。自动化脚本使用同一监听器上的 `/console/v1` API；下文的 API 路径都相对于此前缀。请求字段、权限和状态码见 [Console OpenAPI](../openapi/console-v1.yaml)。数据面 API Key 不能用于登录。

## Console 认证

调用 `POST /auth/login` 后，用响应中的短期 Access JWT 发送 `Authorization: Bearer <token>`。浏览器在内存中保存 JWT，用 `HttpOnly; Secure; SameSite=Lax` Cookie 调用 `POST /auth/refresh` 续期。刷新会轮换 Cookie；重放旧值会撤销该会话。禁用用户、改密、登出或变更角色会使相应旧会话失效。

在头像菜单的「登录会话」按浏览器和当前会话标记识别设备，撤销指定会话或除当前设备外的全部会话。`last_seen_at` 是最近一次刷新时间，不是最后一次 API 访问时间。

### 创建或邀请账户

- **邀请一个人**：管理员在「用户」创建 `invited` 账户，可设置非负初始 USD 余额（默认 `0`）。通过安全渠道将只显示一次的邀请令牌交给用户；用户须在 7 天内设置密码并激活。未设置密码的账户不能直接改为 `active`。令牌丢失或过期，在用户详情重新签发；旧令牌随即失效。
- **开放自助注册**：管理员在「注册邀请码」指定目标组、初始余额和使用条件，把邀请码交给注册人。用户凭邀请码、邮箱、名称和密码注册，成功即登录，无需邮件确认。邀请码区分大小写，长度 12–128 个字符且不含空白；明文只在创建时显示。未设次数或期限即不限次数或不过期。调整设置只影响后续注册；换码时先建新码，再停用旧码。

每个用户属于一个组。邀请时未指定组的账户按角色进入内置默认用户组或管理员组；自助注册使用邀请码指定的组。

### 协助用户恢复密码

1. 对**已设置密码的 active 用户**，管理员可在用户详情输入自己的当前密码，调用 `POST /users/{id}/temporary-password`。不能为自己签发；失去管理员访问权限时用[主机恢复命令](security.md#紧急重置管理员密码)。未设置密码的用户走邀请流程；暂停或停用的用户需先恢复状态。
2. 把只显示一次的临时密码安全交给用户。签发会替换原密码、使此前的临时密码失效并撤销该用户的 Console 会话，不修改数据面 Key 或余额。临时密码有效期为 24 小时；过期后需重新签发。
3. 用户用临时密码登录后，`password_change_required` 为 `true`；此时仅可刷新、退出或调用 `POST /auth/complete-password-reset` 设置不同的新密码。成功后服务签发普通会话，撤销原受限会话。

## 普通用户接口

登录后首先看到个人概览。用量报表和请求日志限定为本人，即使是管理员也一样。查看全局数据使用管理区的[花费统计或请求日志](observability.md#先选择视图)。

### 创建与撤销 API Key

在「API 密钥」创建 Key，从 `GET /me/api-key-options` 返回的范围中选择渠道组或逻辑渠道，并按需设置 RPM、并发与[软额度](billing.md)。自助 Key 有 `proxy` 和 `models.read` 权限。

可选范围取自用户单独指定的 Policy；未指定则继承用户组默认 Policy。选组授权其当前及以后加入的渠道，仅需固定渠道时应直接选渠道。未分配或停用的 Policy 不提供目标，也不能用于创建 Key 或修改授权范围。收紧 Policy 不会自动收回既有 Key 的授权，需检查并修改这些 Key。

撤销会永久停用 Key，但保留可见记录。删除则擦除已存的明文密钥并从列表隐藏；日志和审计仍保留原 Key ID。

### 查看 Codex 额度

管理员通过用户组的 `visible_codex_quota_group_ids` 授予额度查看权。这与 Key 使用渠道的权限分开：本人可以只读查看指定组引用的账号、套餐和主次窗口，同一账号只显示一次。窗口费用是该凭证**全部调用者**的合计，不是个人账单；不会提供其他用户、请求、管理员标签、Token 或代理明细。未获授权和不存在的凭证均返回 `404`。

## 管理员接口

| 要做的事 | Console 入口 |
| --- | --- |
| 接入服务商、绑定密钥 | 上游接入、[上游凭证](upstream-credentials.md)；订阅账号使用 [Codex](codex.md) |
| 发布客户端模型 | 渠道配置 → 操作能力；模型配置 → [上架与路由](routing.md#多个上游接入同一模型)或[价格同步](billing.md#导入目录价格) |
| 设置请求策略 | 系统设置 → 连接与协议、路由与健康；[进程配置与系统设置的区别](production-configuration.md) |
| 查看运行状况 | 系统负载、全局请求日志和[花费统计](observability.md)；审计日志用于核对管理操作 |

### 修改和删除用户

用户详情用 `PATCH /users/{id}` 修改选定字段。例如只改余额不会改角色；把 `default_api_key_policy_id` 设为 `null` 即恢复继承。管理员也可设置用户自己的 `websocket_enabled` 偏好，之后用户仍可自行修改。

批量修改一次最多操作 100 个用户，按每个用户的 `updated_at` 检查版本。状态、组、策略覆盖或余额（设置、增加、扣减）一起提交；一项冲突则整批不生效。不能暂停、停用或删除当前管理员，也不能删除最后一名活跃的非系统管理员。

删除用户需要详情 `ETag` 与确认。删除后邮箱可重新使用；用户已匿名化，会话和邀请失效，所属普通 Key 的明文被擦除。历史请求及审计仍使用原用户和 Key ID。

### 管理用户组与默认策略

在「用户组」设置默认 Policy、可见 Codex 额度组以及 `filter_fast_mode`。开启 Fast 过滤后，成员的 Chat Completions 和 Responses（含 WebSocket）请求会移除顶层 `service_tier`，其余请求继续转发；上游、请求倍率和日志都不再使用该字段。

删除自定义组时，成员按角色移入对应内置组，继承策略和过滤随新组生效；关联邀请码停用，既有 Key 的授权不变。两个内置组可修改设置但不能删除。

### 保存、并发与删除

编辑带版本的详情时，先 `GET` 取得 `ETag`，保存或删除时发送 `If-Match`。遇到 `409` 请载入最新版本、比较并重新提交；个人 Key 页面会在放弃未保存草稿前请求确认。运行时更改在本进程提交后发布，其他进程在周期重载后生效，在途请求继续使用原配置。

删除操作的影响取决于资源。删除能力会移除引用它的候选和空层，无候选规则变为停用草稿。删除计价模型还会停用其规则，清除使用它的定时测试模型和计价引用；同名重建不会改写历史费用。删除接入、凭证、组或渠道前应先检查并解除阻塞依赖。直接授权属于原 UUID，不会转给同名新资源。

### 测试代理出口

在代理编辑页测试草稿，会通过该代理访问 ip-api.com，显示观察到的出口 IP、归属和耗时。测试忽略 `enabled` 与 `no_proxy_hosts`，不发布草稿或改变渠道健康。更换 scheme、host 或有效端口后须重新输入代理凭据。使用前核对[外部查询的明文 HTTP、用途和限流限制](../reference/ip-api-proxy-test.md)。

### 查看渠道状态报告

在操作能力上开启 `status_statistics_enabled`，该能力和可用模型就会纳入对应组及 API 格式的报告。组本身没有统计开关。
