# 管理连接器插件

> 状态：当前实现；新插件生命周期改造尚在完整验收中。

## 运行边界

`general` 内置。Codex 由独立
[ai-gateway-connectors](https://github.com/oai404iao/ai-gateway-connectors)
仓库发布，网关发行包不包含它，也没有内置回退。
插件是可信原生代码，安装权限等价于以网关进程权限执行代码；只使用审查过的制品。

## 配置目录

```toml
[plugins]
directory = "/var/lib/ai-gateway/plugins"
```

目录必须是绝对路径、由运行用户管理，且不能经符号链接访问。
运行用户需要写入权限，以管理安装 staging 和不可变制品。
目录由一个进程独占；插件生命周期管理当前按单实例部署，不支持分布式安装协调。
Compose 使用 `gateway-plugins` 持久卷，entrypoint 在降低权限前准备其所有权。
插件目录需要单独备份；数据库/SQLite 配对备份不自动包含此目录。

不再使用 `[[plugins]]` 的逐个 path/SHA 配置。
摘要来自批准的插件包并存入库存；不是取消摘要校验。

## 网页安装

1. 在「插件管理」上传匹配 Linux 架构/libc 的插件 `.tar.gz` 发行包。
2. 用管理员密码确认原生代码管理操作。
3. 等待安装任务完成。安装后默认停用。
4. 选择已安装版本并明确启用。
5. 在插件详情编辑设置。保存后新请求使用新配置，在途请求保持旧配置。

上传限 64 MiB，包内文件和展开总量另有约束。拒绝路径穿越、链接、特殊文件和重复路径。
安装任务可查询；失败或重启中断时不会自动启用半安装制品。

本地安装也可以将包投递到 `<directory>/incoming/`：
先写临时 `.partial` 文件，完成后原子重命名为 `.tar.gz`。
周期扫描安装登记，但仍需管理员明确启用。成功包标为 `.imported`，失败包标为 `.rejected`。
不要原地覆盖 `artifacts/` 中的 `.so`。

## 设置与升级

客户端版本、originator、User-Agent、合成工作区和 Git 地址均在 Codex 插件设置中，
不再位于系统设置。默认值和校验由插件提供，网关只负责存储、并发控制和通用表单。
安装标识、隐私处理和渠道出站策略也由插件实现。

区分插件发行版本、设置 schema 版本和上游请求声明的客户端版本。
更新客户端版本不需要替换插件；修改设置不会改变凭证稳定的安装标识。
已有部署的设置不会因新插件默认值变化而被覆盖。

升级安装新包后，明确选择新制品。兼容版本可以不停机切换，
旧请求仍由旧代际完成。无法安全迁移的配置或状态会拒绝升级，不静默丢弃字段。
回滚同样需要通过配置兼容校验，不保证任意旧版本都能理解新版设置。

停用只禁止新派发和新维护操作，不删除凭证、路由、余额或日志。
相关渠道不可用，其他正常渠道继续工作；重新启用不会重置配置。
升级可能使已有 Responses WebSocket continuation 或未完成 OAuth 授权失效，
客户端需要重新建立上下文或重新授权。

已加载库不在运行中物理卸载；多次版本升级达到进程保留额度后需要维护重启。
删除当前或已加载制品会被拒绝，必要时先取消选择并重启。

## 从旧部署升级

1. 停机并完成数据库/spool 一致备份，保留旧二进制和原配置。
2. 将旧 `[[plugins]]` 改为 `[plugins].directory`。
3. 准备支持 SDK 0.2 协议 2 的 Codex 插件包。
4. 启动网关，让 PG 0071 或 SQLite 0011 迁移旧设置。
5. 登录管理面，安装并启用新版插件，核对迁移值与所需操作。

五项旧设置原值迁移，凭证和财务记录不变。迁移不会自动批准一个磁盘上的新动态库。
缺失插件时管理面仍可用于恢复，但对应数据面请求不会绕过插件发送。
旧网关不支持新版插件协议，不能只回滚网关而继续使用新插件/新数据库结构。
