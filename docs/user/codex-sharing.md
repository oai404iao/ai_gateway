# Codex 拼车

> 状态：当前。固定席位、USD 金额额度、单实例运行；默认关闭。

## 适用范围

拼车把一个用户组绑定到一个专用 Codex OAuth 逻辑凭证。用户的所有 API Key 共用一个
席位额度；仅实际经该凭证转发的请求占用拼车额度。其他已授权普通渠道（例如 DeepSeek）
继续按原规则使用和计费，不扣拼车额度。不是积分、余额充值，也不是把官方配额百分比兑换成美元。

管理员配置每种窗口的整车金额，按固定席位数等分。一次请求按现有计费结果
`cost_amount`（包含请求/时间倍率）同时占用当前主、次窗口，但正常账单只记一次。
已有余额、API Key 累计额度和 RPM/并发限制仍然生效，不会被拼车刷新清零。

例如 4 席、主窗口 `$20`、次窗口 `$100`，每席分别为 `$5`、`$25`。
一次 `$0.80` 请求会使两个窗口分别剩余 `$4.20`、`$24.20`。
金额使用 Decimal，最多八位小数；等分舍去的尾差不分配给任何成员。

**这是带持久化预占的软金额限制，不是单请求最高费用保证。** 实际费用可能超过预占，
并将超额完整记入原窗口；它也可能使整车提前耗尽。应配置一致、合理的模型价格与倍率、
保守的预占金额和较低并发。零价格/零倍率请求不会消耗金额额度。

## 启用

1. 停止旧实例，确保整个数据库只由一个启用拼车的 Gateway 实例提供服务。
2. 给请求日志 spool 配置持久卷，并在启动 TOML 中设置：

   ```toml
   [codex_sharing]
   enabled = true
   ```

3. 启动 Gateway。它在 `request_logging.spool_directory/codex-sharing/` 打开独立账本，
   校验数据库中的账本 ID 并持有数据库连接锁。文件或所有权校验失败会拒绝启动。
4. 在 Console 的 **Codex 拼车** 管理页创建车队：选择用户组、专用凭证、固定席位，
   配置两类窗口总金额、每请求预占、用户/整车 RPM 与并发上限。
5. 显式配置成员 API Key 的渠道授权、模型规则以及凭证可用性，然后启用车队。
   正常配额维护循环会优先刷新拼车凭证；首次需要等待新鲜窗口信息。

创建即保留绑定凭证的保护。暂停、未分配席位或者进程开关关闭都不能直接使用该凭证，
但不阻断其他已授权普通渠道。应在创建/切换前排空旧请求。
已有请求仍使用其准入时的配置快照。

## 与普通模型共存及“仅拼车使用”

在渠道组详情的 Codex OAuth 配置中打开 **仅拼车使用**，该凭证池中的凭证只能通过有效
拼车席位使用。新导入但未绑定车队的凭证也不能作为普通渠道被调用；可识别的同身份副本
同样受保护。该开关在同池 Responses/Images 两个组之间同步，但不会开启 Images、增加
模型规则或赋予 API Key 权限。普通 OpenAI-compatible 渠道组不能开启此模式。

该模式默认关闭，省略更新字段会保留旧值。关闭模式只解除尚未绑定凭证的整池限制，
**不会解除已绑定凭证的席位保护**，也不会清除任何账目。

成员的实际权限仍是既有 API Key 授权与渠道准入条件的交集：属于拼车组不自动获得 DeepSeek、
其他普通模型或 Images 权限。未分配席位的组成员也可以使用自己已授权的普通渠道。
对于已启动的实例，普通请求不依赖拼车账本健康状态；拼车限额、未知用量或窗口故障仅影响
相应拼车请求。启用账本时，原有文件及所有权启动检查仍须通过；失败会拒绝整个进程启动，
本版本不改变这些恢复约束。

从旧版本升级：

1. 排空旧请求，停止旧实例；一致备份数据库和整个持久 spool。
2. 升级并启动新版本，应用 `0055_codex_sharing_only_groups.sql`。它只增加渠道组访问模式，
   不更换拼车 ID、席位、窗口、金额、账本身份或 WAL 格式；在途预占按现有恢复规则保留。
3. 不重建已有车队。检查成员原有 Key 是否已授权所需普通渠道；如未授权，在原 Policy/Key
   页面补齐权限和模型规则，不需要新建用户或实现多用户组。
4. 如希望整个 Codex 池都只供拼车使用，显式打开该池的 **仅拼车使用**；升级不会替现有池
   自动打开此开关或影响未绑定凭证的原有普通访问。
5. 拼车模型和普通模型建议使用清晰分离的路由。若同一个客户端模型规则同时包含普通与
   拼车目标，选路仍遵循既有规则；实际选中普通目标按普通计费。选中拼车凭证后，连接器准备
   或拼车准入失败不会自动转到普通凭证。要固定某模型走拼车，请不要在它的规则中混入普通目标。

## 固定席位

- 1–100 个固定编号席位，一个用户最多占一席；空席不把额度借给其他人。
- 替换成员继承该席位已经使用和预占的额度。用户调换席位也保留本窗口自己的累计使用。
- 清空、重新加入、换 API Key、重新授权、重启或刷新页面均不重新发额度。
- 新增席位及预算调整分别在对应的下一金额窗口生效，主、次窗口可能分批切换。
  当前窗口已经冻结的席位数与限额不会被改写。
- 当前不支持缩减已保存的席位数、删除车队或更换绑定。绑定的用户组和凭证不能删除；
  停用车队/凭证保留账目，凭证失效时重新授权原记录。
- 成员调出用户组或被停用后不能继续请求。旧席位记录可保留用于追溯，也可清空或替换；
  保存其他设置不要求管理员先清理这些历史占位。

## 窗口与刷新

只使用凭证当前实际提供的窗口，不硬编码“五小时/一周”。单窗口凭证只约束该窗口。
每个请求在发送上游前预占时绑定金额窗口；跨窗完成仍结算到预占时的窗口，不结转。
普通窗口跟随网关确认的上游周期记录，单独刷新发生切换的窗口。

上游整数 `0%` 的周期 ID 和重置时间可能长期滑动。此时首次预占或待生效的席位/预算变更
冻结已观察到的预计
边界；只有该边界已过，并且取得边界之后的新鲜 `0%` 观测及未来重置时间，才推进一次
金额窗口。`0%` 观测可继续校准尚未锚定窗口的预计边界。这是网关的金额窗口
推断，不是对官方未公开的小数配额或绝对容量的保证。

没有消费但已申请扩座/调预算的零窗口也会固定边界，避免空车永远等不到配置生效。
新增席位需要等待所有相关窗口支持新的席位数，可能要等较长的那个窗口。

页面刷新、普通配额轮询及 Token 刷新本身不补额度。观测超过 180 秒、未来时钟偏移过大、
窗口已过期或应有窗口不完整时停止拼车准入，等待同步；不会单靠本地定时器发额度。
上游 reset-credit 操作也只有在窗口状态被确认后才影响金额窗口。

官方可用性与拼车余额是两个条件：个人尚有金额不能绕过上游耗尽、draining、禁用或健康
限制。凭证应专用于本网关；外部直连消耗无法归属到某个成员。

## 接口和隔离

- Responses HTTP/SSE、每条 WebSocket `response.create` 和显式授权的 Images 共用额度。
  Images 投影不会因拼车自动开启或自动授权。
- 一期拒绝经拼车凭证转发的 standalone search：现有响应没有可计价 usage，不能作为免费
  旁路。同一成员经已授权普通凭证进行的搜索保持原行为。
- 拼车请求只允许使用原绑定凭证的投影。可识别的跨池同身份副本也对外保留保护。
  身份信息不全的绑定凭证需要先重新授权补齐身份。
- 分享凭证不分享对话、搜索上下文、WebSocket 连接或 Session。原有格式权限、会话隔离、
  隐私归一化与出站请求策略保持不变。计划任务不会探测受保护的共享渠道。
- 用户在 **我的拼车** 查看自己的席位、已用/继承金额、预占、剩余和上游观测。管理员
  可查看各席位；个人接口不暴露其他成员、凭证 ID、邮箱或 OAuth Token。

## 故障与恢复

预占必须写入本地日志并完成 fsync 后才允许发送。结算按请求 UUID 幂等处理。
发送后断开、缺失 usage 或进程重启不会退款：保留预占，冻结受影响的成员/席位，
由后台从耐久请求日志恢复实际 `cost_amount`。仍无法确认的请求等待相关窗口结束。
已经确定尚未发送的准备失败可以释放预占。

账本包含带校验和、序列号的 `ledger.wal` 和原子替换的 `ledger.json`。
不要手工修改、单独删除、回滚或者复制成第二个正在运行的账本。
目录、文件应分别保持 `0700`、`0600`；需要支持文件锁、原子 rename 和 fsync 的可靠存储。
账本故障、等待超时或数据库所有权连接失效时，拼车请求 fail closed。
这不是 HA、分布式配额租约或自动故障转移方案。

备份/迁移应先停止并排空 Gateway，再同时保存数据库、整个请求日志 spool 与
`codex-sharing` 子目录；恢复同一个一致性时间点，先验证单实例所有权后再放流量。
只恢复旧账本可能撤销已发生的使用，不能用于“重置额度”。新增空卷也不能替代旧账本。
本地保留当前、仍在途及最近 90 天的窗口状态；长期历史仍依赖原有请求日志。
账本及日志各有 64 MiB 安全上限，达到上限会停止拼车准入，需要检查容量与恢复状态。

常见错误：

| Code | 含义 |
| --- | --- |
| `sharing_quota_exceeded` | 席位或整车金额已用尽/已预占 |
| `sharing_rate_limited` / `sharing_concurrent_limited` | 用户或整车流控 |
| `sharing_membership_required` | 暂停、无席位或不再具备成员资格 |
| `sharing_usage_pending` | 存在未确认用量，等待对账或窗口结束 |
| `sharing_window_unavailable` | 缺失、过期或陈旧的窗口信息 |
| `sharing_unavailable` | 本地账本或单实例所有权不可用 |
| `sharing_operation_unmetered` | 当前操作不能参与金额计量 |
