# 管理上游凭证

> 状态：当前。

上游凭证让 Gateway 访问服务商；客户端 API Key 则让调用者访问 Gateway。要把一个密钥用于多个渠道，只需建立一次凭证，分别将渠道绑定到它。

## 创建并绑定凭证

1. 在「上游凭证 → 通用」创建静态凭证，填写认证方式、密钥和允许的上游 Base URL。订阅账号使用[专用 Codex 流程](codex.md)。
2. 在「上游接入」配置 Base URL、连接器、代理和超时。打开「渠道配置」中的逻辑渠道，选择接入和凭证。无需认证的通用服务可明确选择无凭证，Codex 必须绑定兼容凭证。
3. 按[路由指南](routing.md)添加操作能力、模型候选和 Key 授权。多个渠道共用凭证时仍分别授权；改绑不会把已完成或在途请求的费用转移到另一账号。

## 限定允许的目标地址

凭证范围按**完整 Base URL** 匹配，不是域名、子域或路径前缀白名单。仅允许 HTTP/HTTPS；协议、主机大小写、默认端口以及末尾 `/` 规范化后比较。路径大小写、内部重复 `/` 和非默认端口仍有区别。地址不能含用户信息、query、fragment、空白、控制字符或反斜杠。

更换接入的 Base URL 时，先把新目标加入每个引用凭证的允许范围，再改接入。最后确认没有渠道引用旧目标才能移除它，停用渠道不等于解绑。模型发现也检查凭证是否启用、类型和目标地址是否匹配。

## 轮换、停用与删除

| 操作 | 对引用渠道的影响 |
| --- | --- |
| 轮换密钥 | 引用同一凭证的所有渠道随新快照改用新密钥；已发送的请求不能撤回。若需独立轮换，创建另一个凭证并改绑渠道。 |
| 停用或恢复 | 临时阻止或恢复新请求，不删除路由或改为无认证转发，不重置余额与用量。 |
| 解绑或删除渠道 | 解除该渠道的引用，不修改凭证或其他渠道。 |
| 删除凭证 | 先解除所有未删除渠道的引用，包括停用渠道。删除擦除密钥或 OAuth Token，释放维护代理，保留历史身份。外部 Token 撤销需在服务商处操作。 |

轮换、改绑或启停可使已有 WebSocket 上下文失效。遇到 `404 previous_response_not_found` 时由客户端[重发完整请求](websocket.md#继续上下文或恢复连接)。

## 使用 Console API 自动化

管理员用 `/console/v1/routing/upstream-credentials` 管理通用凭证。创建时提供 `secret`；更新省略表示保留，`null` 或空白值会被拒绝。认证类型不能原地修改。列表不返回密钥，但管理员可在详情读取静态密钥；响应带 `Cache-Control: no-store`。更新和删除均须使用详情的 `ETag` 发送 `If-Match`。

逻辑渠道和模型发现使用 `credential_id`，不传密钥。Codex 的 OAuth、刷新及显式导出有独立端点；维护代理不替代接入的转发代理。精确请求和响应见 [Console OpenAPI](../openapi/console-v1.yaml)。
