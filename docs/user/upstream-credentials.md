# 上游凭证管理

> 状态：当前。通用与 Codex 凭证独立管理，通过逻辑渠道显式绑定。

## 身份与渠道

客户端 API Key 用来访问网关；上游凭证用来访问服务商，两者独立。
渠道组组织逻辑渠道，不拥有凭证，也不限定连接器。同组可包含不同连接器的渠道。
每个逻辑渠道通过 `credential_id` 引用一个凭证；通用渠道还可使用 `null` 表示无认证，
Codex 渠道必须绑定 Codex 凭证。
同一个凭证可以供多个逻辑渠道复用，但必须允许其所选接入的完整 Base URL。
一个逻辑渠道可以有多个独立操作能力，不支持跨协议转换。

Console 的“上游凭证”按“通用 / Codex”管理。管理员先配置凭证、接入和渠道组，
再到逻辑渠道页面绑定；导入凭证不自动创建接入、渠道、能力、路由或授权。
“渠道配置”使用平铺渠道列表，渠道组作为筛选条件；打开渠道详情，在“渠道接口能力”页签
查看、新建或编辑操作、模型目录和变换，不复制密钥或隐式创建授权。
接入连接器使用 `general`（通用）或 `codex`；凭证类型 `codex_oauth` 保持不变。
传输不再单独配置，Responses HTTP 与 WebSocket 使用两个独立操作能力。
要让渠道使用独立的密钥生命周期，应创建另一个凭证并重新绑定。

## 目标范围

每个活动凭证都有非空的“允许的 Base URL”。静态凭证由管理员配置，
Codex 导入使用连接器配置的目标地址；迁移保留旧绑定的目标范围。按完整地址规范化后匹配：

- 仅支持 HTTP/HTTPS；协议、主机大小写及默认端口按 URL 规范处理。
- 末尾 `/` 与现有端点拼接规则一致，可等价匹配。
- 路径大小写、内部重复 `/`、不同路径及非默认端口不自动合并。
- 不允许 URL 用户信息、query、fragment、空白、控制字符或反斜杠。
- 这不是域名、子域或路径前缀白名单。

修改接入 Base URL 前，先显式把新目标加入全部引用凭证的范围。
任何尚未删除的渠道仍引用旧目标时，不能从范围中移除旧目标；停用渠道或停用渠道组不等于解绑。
模型发现同样校验凭证类型、启用状态和目标范围，不能绕过范围临时注入密钥。

## 轮换、停用与删除

- 轮换密钥会在一次完整运行时快照发布中更新所有引用渠道。已发送的请求不保证撤回。
- 停用凭证会阻止相关渠道的新请求，不删除路由，也不会改为无认证转发。
- 恢复凭证不会重置用量、余额或配额。
- 渠道解绑不修改或删除凭证；删除渠道也只解除其引用。
- 只要还有未删除渠道引用凭证，就不能删除它，包括停用渠道。
- 删除凭证清除静态密钥或 OAuth Token，解除维护代理引用，并保留不可恢复的身份墓碑。
- 拼车绑定的逻辑渠道和账号不能改绑或删除；令牌轮换不改变拼车金额或窗口。

轮换、凭证启停和渠道改绑会使旧的 Responses WebSocket 连接身份失效。
失效后的 continuation 返回 `404 previous_response_not_found`，不会把增量请求发送到新连接；
客户端应发送完整请求重新建立状态。即使新旧密钥文本相同，改绑也不会复用旧身份的连接。

## Console API 变更

管理员凭证集合：`/console/v1/routing/upstream-credentials`。
详情、更新和删除使用 `/{id}`；详情提供 `ETag`，更新和删除要求 `If-Match`。
列表不返回密钥，管理员详情允许读取静态 `secret`，并使用 `Cache-Control: no-store`。
审计不记录密钥内容。创建时必须提供 `secret`；更新省略它表示保留，`null` 或空白值会被拒绝。
认证类型不可原地修改。

逻辑渠道集合为 `/console/v1/routing/logical-channels`，接入集合为
`/console/v1/routing/accesses`，能力集合为 `/console/v1/routing/capabilities`。
逻辑渠道创建、更新和模型发现必须显式提供 nullable `credential_id`。
逻辑渠道创建、更新还必须提供 `sharing_only`；只有 Codex 渠道支持设为 `true`。
旧的 `upstream_auth_kind`、`upstream_auth_header_name`、`upstream_api_key` 写入字段不再接受，
外部 Console 管理脚本必须升级；渠道详情也不再返回密钥。
精确请求/响应形状以 [Console OpenAPI](../openapi/console-v1.yaml) 为准。

## Codex

统一凭证列表展示 Codex 的稳定身份及逻辑渠道引用，但不返回 OAuth Token。
在“上游凭证 → Codex”中导入、授权、更新、刷新、导出或删除账号。
OAuth 操作使用 `/console/v1/routing/upstream-credentials/codex` 及其子路径，
不再带渠道组参数；通用静态密钥写入接口不能代替 OAuth 生命周期操作。
一个凭证可被多个兼容的逻辑渠道复用；这些渠道的授权、能力和路由始终独立。
维护代理只用于账号刷新、额度检查等连接器维护操作，不修改逻辑渠道接入的转发代理。
凭证 UUID、额度窗口、拼车绑定与账本引用保持不变。旧 Responses/Images 投影转存为一个
逻辑渠道及按原支持范围拆分的操作能力，旧投影 ID 保留在历史身份注册表中。
Codex 渠道可显式配置 Responses HTTP、Responses WS、搜索、图片生成和图片编辑能力，
不能配置 Chat Completions。旧图片能力的停用状态在迁移中保持不变。
Key/Policy 保存固定逻辑渠道范围；已授权渠道的现有和后续能力共享授权，
但能力启用、模型目录及对应操作路由仍需独立配置。之后加入已选组的新渠道不会自动获权。
删除任意渠道能力会同时移除其全部路由候选；空层被清理，无候选规则保留为停用草稿，
不删除客户端模型、渠道授权或计费历史。

重新导入同一可识别账号会更新原凭证，不复制渠道、不更改其模型目录或路由；
多个历史凭证匹配同一账号时拒绝含糊更新，不静默合并。拼车选择逻辑渠道，
同一可识别账号最多绑定一辆车；其他引用或别名渠道不能绕过保护。详见[拼车](codex-sharing.md)。

每个新请求在选路时记录凭证归属。渠道后来改绑，不会把已完成或在途请求的费用转移到新账号。
旧请求仍按不可变历史身份注册表归属；明确无认证的新请求不会回退到旧凭证。

## 升级

升级前停机并备份；SQLite 使用[成对数据库/spool 备份](sqlite.md)。
迁移逐条提取普通渠道凭证，不因相同密钥文本自动去重。
后续统一迁移移除 Codex pool 和凭证的渠道组归属，将旧组的“仅拼车使用”复制到其现有活动渠道，
并把拼车绑定到原逻辑渠道；未来新增渠道不继承该开关。凭证、渠道、能力、座位、窗口和账本身份不变，
不重置余额或费用；旧的未完成组绑定 OAuth 流失效，需要重新发起授权。
非法认证或目标地址的停用草稿也会阻止迁移；错误仅报告渠道 UUID，
应使用旧版 Console 修复或删除该草稿后再升级。
失败迁移整体回滚，不能通过清空密钥或放宽范围绕过检查。
回退使用完整备份与匹配的旧二进制，不把新 schema 交给旧版本继续写入。
