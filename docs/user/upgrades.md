# 切换存储基线与回滚

> 状态：当前。

PostgreSQL 和 SQLite 都使用新的 v1 数据库基线。**这次切换是新建实例，不是原地升级**：网关可以重新打开本基线的数据库，但会拒绝以前的迁移历史，也不会回放以前版本的请求日志。以下流程保留原有账本，不把历史数据转入新库。

## 保存现有账本

1. 停止接受新请求，等待在途请求结束。用生成记录的版本排空每个实例的本地完整终态，再核对数据库入口、计量及结算积压。只有 intent、没有可信终态的请求，保留 UUID 与上游证据，不重发、不记零。
2. 停止所有实例和 worker，关闭自动拉起。以同一停写点备份数据库和**每个实例的完整 spool 根目录**。SQLite 用与该库匹配的程序做停机成对备份；PostgreSQL 做一致的逻辑或物理备份。
3. 保留原程序、镜像身份、配置、密钥和插件制品。在隔离位置用原程序演练恢复，需要查历史授权、金额或未决费用时使用这套账本。不要修改迁移记录或清空旧卷来通过启动检查。

## 请求日志目录切换

给新实例分配**独立的空 spool 根目录**，通过 `request_logging.spool_directory` 指向它。旧目录、检查点和准入槽随原数据库留存；不要挂载或复制到新实例，不要将旧终态写入新数据库。新实例的积压为零只描述自己的流水线。

## 启动与验收

- **PostgreSQL：** 初始化一个新的空数据库，授予网关账户建表权限，让 `[database].url` 明确指向新库。使用[生产 Compose](production-deployment.md)时，以新的项目名创建专用卷，核对数据库和 spool 卷名、配置及密钥挂载；切勿借用原项目的卷。
- **SQLite：** 在新的专属 `0700` 目录使用新的数据库文件路径。不要将旧文件、sidecar 或旧快照作为新实例的初始库。权限和命令见 [SQLite 部署](sqlite.md)。
- 按[快速开始](quickstart.md)创建首个管理员，重新配置上游、价格、操作路由和渠道授权，给客户端签发新 Key。新账本不继承余额、已结算额度或历史费用；审定新账户的余额、限额及授权，再接入流量。
- 检查 Console 登录、Key 可见模型和目标路由，再验证新实例的日志与结算。`/health` 只说明进程存活，生成请求可能产生费用。

同一基线的日常重启继续使用本实例原有的数据库和 spool；恢复本基线的备份时，也要从**同一恢复点**成对恢复。

### 在已有 PostgreSQL 服务器上建新库

使用有 `CREATEDB` 权限且可将新库分配给网关角色的数据库管理员，连接维护库（如 `postgres`）执行以下 SQL。示例假设 `ai_gateway` 角色已存在；将 `ai_gateway_v1` 换为未使用的库名。若名称已存在，先核对部署记录，另选名称，不要删除原库。

```sql
CREATE DATABASE ai_gateway_v1 OWNER ai_gateway TEMPLATE template0;
```

例如同机 PostgreSQL 使用 `url = "postgres://ai_gateway@127.0.0.1:5432/ai_gateway_v1"`，凭据仍通过受保护的 `database.password_file` 提供。第一次启动前，核对这个 URL 和新 `request_logging.spool_directory` 都与原部署分开。

## 回滚

停掉新实例并保存它独立产生的财务记录。用**原版本程序和原实例的成对备份**恢复原部署，核对授权和未决记录；已经在新实例执行的上游请求需要单独对账，不会因回滚撤销或合并。确认只有预期的实例接收流量，再切回入口与客户端凭据。
