# 升级与回滚

> 状态：当前。

网关在启动时迁移数据库。升级单位是网关制品、数据库、spool、配置和插件，不只是镜像标签。全新安装见[生产部署](production-deployment.md)。

## 执行升级

1. 从当前版本到目标版本逐项阅读 [Changelog](../../CHANGELOG.md)，找出配置、授权、数据库和插件变更。大库先在隔离副本测迁移时间及磁盘/WAL 用量，试做一次恢复。
2. 阻止新请求，等待在途请求完成。按下文[请求日志目录切换](#请求日志目录切换)处理本地积压，再停止所有旧实例和 worker，确认不会自动重启。
3. 在同一停写点备份数据库与**每个实例的完整 spool 根目录**。SQLite 使用[离线成对备份](sqlite.md)；PostgreSQL 使用一致的逻辑或物理备份。同时保留旧制品、TOML、JWT 密钥、插件目录。Compose 升级复用原持久卷与项目名。
4. 换用匹配的配置和插件，启动目标版本执行迁移。若失败，先查已提交到哪个版本：PostgreSQL 的 `0034`、`0046` 是独立提交边界。只有确认数据库仍匹配旧版本时，才能用旧程序按报错的资源 ID 修复配置；否则先恢复配套备份，在恢复副本上修复，再重试迁移。
5. 恢复流量前核对 Console、Key 授权、路由、历史金额和日志/结算积压。`/health` 成功只表示监听器在运行，不能证明路由可用。

## 回滚

先停写并保存切换后产生的数据。跨 spool 布局、schema 或设置的不兼容边界时，在隔离位置恢复升级前同一停写点的整套备份，用匹配旧制品核对账本。逐请求核对恢复点以后的上游使用、事实及回执，再恢复流量。只切回旧程序不能恢复新布局里的终态，也不要让旧实例写入已迁移数据库，或让恢复副本与原账本同时接收请求。

## 请求日志目录切换

保留原 `request_logging.spool_directory` 设置。新版在其 `journal-v2/` 子目录写入和恢复日志，仍使用根目录的 `spool.lock`。旧布局根目录的 `events.log`、`checkpoint` 和 `admissions/`（包括完整终态槽及结果未知的 intent）留在原处；新版不回放、搬移或删除它们。**不要把旧文件复制进新子目录。**

- **只在旧实例本地的终态：** 要计入账单，必须在升级前用匹配的旧版本排空。逐实例确认完整终态槽已恢复、spool 待处理字节为零，并核对数据库入口及结算进度。未排空就切换，新版不会补记这些日志或费用。
- **只有 intent、没有可信终态：** 保留原始证据，按请求 UUID 核对数据库记录与上游用量证据；不能当作零费用，也不要重发请求。
- **已提交数据库的记录：** PostgreSQL 和 SQLite 仍按各自的有序迁移升级。数据库入口中受支持的记录继续计量、结算和投影；既有事实和回执不因本地目录切换而重算。更早且不受支持的入口格式须在旧版本排空，见[格式边界](../development/request-log-durability.md#journal-与升级边界)。

## 渠道组授权变更

已选择组的 Key 现在获得该组所有当前成员的访问权，包括之前只授予部分成员的 Key。空组以后新增成员也会生效。升级前检查 Key 和 Policy 的 `allowed_group_ids`：需要固定范围时，用明确的渠道授权替换组选择。只改 Policy 不会收窄已签发的 Key。

两版对同一组选择的解释不同，即使 schema 相同也不能混跑。升级后若改过授权或组成员，回退时须用对应版本的恢复点核对、重建有效授权，再开放流量。

## 上游拓扑硬切换升级

PostgreSQL `0065–0069` / SQLite `0005–0009` 转存旧路由和凭证绑定，形成管理组、接入、逻辑渠道、六种操作能力和显式路由候选。预检拒绝无法表示的停用草稿、非法凭证范围或路由；旧组绑定 OAuth 流需重新授权。详见[上游实体与授权迁移](../development/upstream-identity-capabilities.md)。

## Codex 拼车移除升级

从使用拼车席位的版本升级时，删除 TOML 的 `[codex_sharing]` 段。迁移停用受保护渠道，保留普通日志、计量事实、结算和配额历史。恢复流量前重新审核受影响渠道、模型、Key 和 Policy，然后手动启用需要的渠道。席位不再授予权限或提供金额窗口保护。

旧 `codex-sharing/` WAL 与检查点不再回放，作为历史证据随备份保留。仍在使用的请求日志 spool 必须继续挂载。

## 其他需要人工处理的版本边界

| 跨过的变更 | 升级动作 |
| --- | --- |
| 清理旧列（PG `0074` / SQLite `0014`） | 日志查询改读 `request_protocol`。`request_logs.attempts`、`api_keys.last_used_at` 和 `audit_logs.source_ip_prefix` 的历史值不会转存；需要留查时保留升级前备份。SQLite 会重建请求日志表和索引，在副本上按实际日志量确认磁盘余量和停机时间。 |
| 移除 MCP（PG `0053`） | 删除 `[mcp]` 配置与 `mcp-server` 构建参数。历史 MCP 日志归入 `client`。 |
| 失败费用与独立计量（PG `0061–0063`） | 核对历史失败/取消退款；确认原 `all` 路由只展开为迁移时的成员。为事实与回执回填预留磁盘及停写时间，见[独立计量](../development/independent-metering.md)。 |
| 从内置或逐路径 Codex 插件升级 | 按[插件指南](connector-plugins.md)配置托管目录，安装并启用匹配协议的制品。 |

更早版本的字段删除、配置变化与迁移顺序见相应[发布记录](../../CHANGELOG.md)与 [SQL migrations](../../migrations/)。
