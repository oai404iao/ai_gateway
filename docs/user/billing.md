# 计费、额度与价格

> 状态：当前。

网关以 USD 记录模型价格、请求费用、余额和 API Key 额度。金额取决于请求时的价格与可解析用量，不等同于服务商账单。

## 理解费用与额度

Key 的额度是软上限：只检查已结算金额，不为在途请求预留费用。并发或长请求可以超出上限，余额也可为负。网关不提供充值、退款或货币兑换。

只有成功且可计价的请求按用量扣费。`failed` 和 `cancelled` 的费用固定为 `0`，即使已观察到部分 usage；未知结果、无价格证据或未派发的拒绝不等于「已按零额结算」。结算回执独立于可查询日志，删除日志不会撤销费用。核对回执见[日志与结算](observability.md#跟踪请求日志与结算)。

## 在 Console 编辑价格

在「模型配置」选择客户端模型，打开「配置价格」，填写输入、缓存命中、缓存写入和输出的 USD 基础单价。各价均按模型的 `price_unit_tokens` 计量。计算器可按十进制倍率把参考报价填入草稿，须保存才生效。

按需要设置以下规则：

| 规则 | 何时生效 |
| --- | --- |
| 长上下文档位 `advanced_billing.long_context_tiers` | 按严格递增的输入 Token 阈值选择。达到档位后，对**整次请求**使用该档输入、缓存命中、缓存写入价；可另设该档输出价。 |
| 请求倍率 `advanced_billing.request_multipliers` | 对入口白名单和用户组过滤之后、变换之前的 JSON 使用 JSON Pointer 精确匹配；**所有命中项相乘**。已过滤的 `/service_tier` 不会命中。 |
| 时段倍率 `advanced_billing.time_multipliers` | 按请求开始的 UTC 时间选至多一项。最多 32 个不重叠的周循环窗口；起点包含、终点不含。跨午夜时使用开始日的星期。未命中倍率为 `1`，流式响应或重试跨时段不改价。 |
| 能力倍率 `billing_multiplier` | 按最终选定能力取非负倍率，默认 `1`，不按上游模型名重新选择计价模型。 |

选定档位后，将请求、时段和能力倍率相乘，应用到四类单价。日志保留最终价格快照，之后改价不重算历史。时段倍率大于 `1` 的请求会标记 `Peak`。

使用 [DeepSeek 峰谷预设](../reference/deepseek-peak-pricing.md)时，先填谷价，再核对预设填写的高峰时段和倍率。保存前对照服务商报价。

## 导入目录价格

1. 在模型价格同步页取得 models.dev 报价预览，选择要导入或更新的模型。
2. 确认批量应用。API 调用须带回每个条目的 `provider_id`、`model_id` 和 `preview_token`。所选目录项或其预览字段变化，或本地模型在预览后被创建、修改、删除，均返回 `409`，整批不写入。重新预览、核对后再提交。
3. 检查可选倍率。若目录中 `experimental.modes.*.provider.body.service_tier` 对输入、缓存和输出使用统一倍率，导入会生成 `/service_tier` 规则；无法表达时仍可导入基础价格。更新只替换相同匹配条件的目录倍率，保留其他本地请求倍率及管理员设置的 UTC 时段。

## 核对结果

个人请求日志可查实际费用和 `Peak` 标记；全局花费可按用户、Key 或逻辑渠道筛选。详见[统计范围与时间口径](observability.md#查询花费)。
