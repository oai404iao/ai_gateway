# 上游身份、渠道能力与路由目标重构

> 状态：部分实现。第一阶段已实现并通过验收；第二、三阶段改为联合切换，
> 当前只实现能力约束及后端无关的路由/目标授权迁移规划，尚未接通数据库和运行时。
> 同一 PR 按独立 commit 推进，一次联合升级交付。协议转换不在本次范围。

## 范围与决策

重构前普通渠道同时保存接入地址、认证材料、协议格式和模型目录；Codex 则把一个逻辑身份
投影为 Responses、Images 两个渠道。搜索依附 Responses 能力开关。
当前实现入口见[架构](architecture.md)、[Codex Connector](codex-oauth-connector.md)、
[数据库架构](database-architecture.md)和[拼车账本](codex-sharing.md)。

本次把身份、接入、能力和客户端路由分开，保持以下约束：

- 客户端 API Key 始终是网关入站身份，不与上游凭证合并。
- 一个渠道明确引用至多一个上游凭证；无认证接入使用空引用，不创建假密钥。
- 一个凭证可供多个兼容渠道使用；复用必须满足显式目标范围，不能把密钥发到任意 URL。
- 连接器描述服务商行为，认证类型描述认证材料及其注入方式，客户端协议描述入站契约。
- 能力存在、能力启用、路由配置、用户授权分别判断；任何迁移都不得自动扩大权限。
- 控制面编译完整不可变快照后原子发布；数据面不增加逐请求数据库访问。
- 不引入第二层隐式凭证池选路，不自动把新凭证加入模型候选。
- 不新增协议转换、自动降级、万能中间消息协议或跨格式重试。

管理接口采用明确的破坏性切换：渠道写入与模型发现改用凭证引用，移除内联认证字段，
Console、OpenAPI、生成类型、测试及使用说明同步更新。不维护旧写入兼容通道。

## 目标实体与所有权

```text
上游凭证 ───────┐
               ├── 渠道 ── 渠道能力 ── 能力模型目录
上游接入 ───────┘      │
                      └── 渠道组

客户端计价模型 ── 客户端协议规则 ── 路由候选
                                      │
                                      └── 渠道能力 + 上游模型
```

### 上游凭证

凭证拥有稳定 UUID、显示名称、认证类型、生命周期和受保护的认证材料。
静态凭证保存 Bearer 或指定 Header 的密钥；Codex OAuth 保留自己的 Token、刷新、
账号身份和配额生命周期。通用身份记录不复制 OAuth Token。

凭证不是渠道模板，不保存路由权重、客户端模型、协议格式或单一共享模型列表。
相同 secret 不代表同一个业务身份；不通过 secret 内容做自动去重。

凭证目标范围采用规范化后的完整 Base URL 精确匹配，而非任意子域、URL 前缀或只匹配域名。
地址不允许 userinfo、query、fragment；规范化规则统一用于保存、渠道绑定、模型发现和
快照编译。扩大范围是独立的管理员凭证修改，需要 ETag 和审计。
Codex 目标与连接器兼容性由其专属管理流程验证，普通凭证接口不得把 OAuth 身份绑定到
普通连接器，也不得修改其 Token 或解除拼车保护。

规范化仅接受 HTTP/HTTPS，以项目现有 URL 解析器的规范序列化为基础：scheme/host
大小写与默认端口等价，末尾 `/` 按现有端点拼接语义移除；路径大小写、内部重复 `/`、
非末尾路径段及保留的百分号转义不得合并。拒绝首尾空白、控制字符和反斜杠，避免不同
HTTP 组件以不同目标解释输入。迁移保留原始地址作为范围输入，统一由同一个 Rust
规范化器解释，不能用 SQL `lower` 或前缀比较替代。

### 上游接入

拥有连接器类型、Base URL、默认网络策略。认证材料不属于接入。
第一阶段不单独引入接入表，暂保留渠道的 Base URL、组的连接器类型及现有网络配置；
第二阶段再集中所有权，避免第一阶段同时改写接入与认证语义。

### 渠道与能力

渠道是确定的接入与身份组合，属于一个管理组；无需引入多组多对多标签系统。
能力描述该组合支持的上游协议、操作、传输组合、模型目录和能力级开关。
连接器实现给出能力上限，管理员配置只能收窄，不能通过勾选声明未实现能力。

模型目录按能力维护。图片生成与编辑分别表达；不能根据操作名称推断无模型语义。
当前普通和 Codex 搜索路径均保留选中候选的 wire model，迁移必须保持模型别名及目录门槛。
HTTP/JSON、HTTP/SSE、WebSocket、multipart 是经过验证的支持组合，不能以几个
独立布尔值生成未经实现的笛卡尔积。

### 客户端路由

计价模型仍是不可变客户端模型身份。协议规则声明客户端可调用契约，路由候选显式引用
目标能力与上游 wire model，保留 priority、weight 和 selection strategy。
原生路径要求客户端操作与目标能力兼容，不能仅凭模型名称相同认为可调用。

## 第一阶段：独立凭证身份

### 持久化与迁移

新增公共上游凭证身份及渠道的 `credential_id`：

| 数据 | 所有者 | 第一阶段行为 |
| --- | --- | --- |
| 静态密钥、认证 Header、目标范围 | 上游凭证 | 唯一持久来源，可复用 |
| Codex Token、账号、刷新 generation、额度窗口 | Codex 凭证扩展 | 沿用专属流程，不复制 |
| Base URL、代理、格式、模型目录、超时 | 现有渠道 | 保持现有职责 |
| 路由权重、优先级、wire model | 现有协议候选 | 不变 |
| 拼车绑定与金额账本 | 现有稳定身份和账本 | 不变 |

PostgreSQL 与 SQLite 均追加有序 migration，不修改已发布迁移。
每个存量有认证的普通渠道创建独立凭证，回填相同认证材料和该渠道的精确目标范围；
即使密钥文本相同也不合并。无认证渠道保留空引用。迁移后渠道不再保存认证材料副本。
第一阶段暂保留渠道表的三个旧认证列为空，并用约束/触发器禁止写入材料；这样不用在
SQLite 中提前重建渠道及其全部历史外键，也无需重写旧 Codex 投影函数。
它们不再是 Console 契约或认证来源，后续渠道能力重构可一并删除这些空列。

Codex 公共身份沿用既有 credential UUID，也就是既有 Responses channel UUID。
两个投影都引用该公共身份。第一阶段可以保留专属表历史列名 `channel_id`，但其含义是
稳定 credential ID；不得以新增 Images 投影、重新导入、刷新、重启等动作生成替代身份。
现有渠道、日志、配额窗口、共享席位、WAL 和结算引用保持原值。

现有 `codex_oauth_credential_channels` 仍是 canonical 投影映射；渠道引用必须与它一致，
数据库保护及快照编译均拒绝不一致、额外投影或普通 CRUD 改绑。公共身份的创建和墓碑更新
纳入同一个 Codex 事务，enabled/deleted 状态以既有 Codex 生命周期为准，不提供第二套
独立开关。普通凭证不得伪装为 Codex 身份。

软删除清除静态 secret 并保留墓碑。活跃渠道引用时拒绝删除普通凭证；删除渠道仅解除引用，
不得顺带删除共享凭证。Codex 删除仍走专属路径及现有绑定保护，不提供通用绕过入口。
这里“活跃引用”指任何尚未软删除的渠道，包括 disabled、auto-disabled 和停用组中的渠道；
删除与范围收窄均检查这些引用，不能把临时停用当成解绑。
迁移失败整体回滚，不新增 PostgreSQL enum commit barrier。

升级预检必须覆盖现有停用草稿：当前实现允许停用渠道保留非法 URL 或未完成认证材料。
预检只报告渠道 ID 和错误类别，不输出原始 URL/secret；存在无法表示的草稿时拒绝升级，
要求先通过旧版管理接口修复或删除，再重新迁移。不静默丢弃 secret、放宽范围或假定无认证。

### 管理契约

新增管理员专用凭证列表、详情、创建、更新、删除接口：

- 列表不含 secret；详情按现有产品策略允许管理员读取静态 secret。
- 新建静态凭证必须提供认证类型、合法 secret 和非空目标范围。
- 认证类型不可修改；需要换类型时创建新凭证并显式重新绑定。
- 更新以 `If-Match` 防止覆盖；省略 secret 表示保留，明确传入新值表示轮换，
  不允许把有效认证静默清空。
- 更新显示受影响渠道；一次凭证轮换在一个控制面事务及一次快照发布中生效。
- 禁用凭证阻止其全部渠道的新请求，但不删除路由或扩大其他权限；恢复后可重新选择。
- 收窄目标范围若使现有活跃绑定非法则拒绝，不默默解绑或降级为无认证。
- 创建、修改、删除及渠道重新绑定写入脱敏审计；日志、错误和 `Debug` 不泄露材料。
- Codex 身份可统一展示，修改、导入、导出、删除仍进入 Codex 专属流程。

渠道创建/修改使用显式 nullable `credential_id`，空值表示无认证。
PUT 不以省略字段暗示保留认证，避免误解绑；旧内联字段通过严格反序列化拒绝。
普通渠道不能引用 provider-managed 凭证。模型发现使用同样的引用、范围和启用状态验证，
不保留另一个任意密钥注入入口。

Console 新增凭证管理入口；渠道表单选择凭证并展示身份，不再编辑 secret。
已有渠道详情保留原格式与路由展示。凭证轮换和渠道重新绑定是两个不同的操作。

### 运行时与安全

完整控制面快照一次性解析静态凭证引用，将不可变认证配置装配到渠道；
不得在每次请求时查库。Codex Token 继续使用独立的凭证 ArcSwap 和既有刷新互斥。
同一请求保持已获取的身份视图；轮换不承诺撤回已发送请求。

失效引用、错误类型、非法目标、禁止的认证 Header 在事务预编译时失败，事务回滚，
不得发布“认证为空”的替代快照。禁用是有效配置状态，选路必须排除对应渠道。
凭证轮换、禁用、解绑必须使不再合法的 WebSocket 池条目不可复用；
会话身份不得因多个渠道引用同一凭证而混池。

凭证拥有不含 secret 的失效 generation；轮换、禁用/恢复、目标范围变更推进 generation，
渠道改绑即使使用相同 secret 也改变连接身份。池键必须覆盖 credential ID/generation，
并对已空闲、当前借出及之后归还的连接执行同一有效性检查；仅清理空闲池不足以保证失效。
旧连接失效后的 continuation 返回 `404 previous_response_not_found` 且不 dispatch；
无 previous-response 的新请求重新连接。禁止用显示名称或更新时间精度代替 generation。
渠道另外持有 `credential_binding_revision`，每次改绑推进，避免 A → 空/B → A 后旧连接
重新变得有效；无认证绑定也受该 revision 隔离。

入站/出站 Header 白名单、Codex 隐私归一化、客户端权限、Images 不可重试、
WebSocket 连接局部状态和拼车准入顺序全部维持。无需更改请求白名单。

### 第一阶段验收

1. 双后端升级覆盖普通 Bearer、Header、无认证、软删除渠道及 Codex 两个投影。
2. 相同 secret 不自动合并；迁移保留 Codex UUID、配额、席位和金额事实。
3. 两个渠道引用同一凭证，一次轮换同时更新二者；改绑一个渠道不影响另一个。
4. 禁用/恢复、非法引用、类型冲突、越界 URL、禁止 Header 和删除在用凭证均有负例。
5. ETag 冲突、审计脱敏、非管理员拒绝、secret 列表不泄露、旧渠道字段拒绝有契约测试。
6. 模型发现、计划探测、HTTP/SSE、WebSocket 认证均来自同一身份来源。
7. Codex 导入、刷新、删除、配额、Images 投影和共享凭证保护有双后端回归。
8. Console 组件与浏览器验证创建凭证、跨渠道复用、轮换及冲突处理。
9. 运行格式、lint、Rust/Console 全量检查、API drift、双后端系统 E2E 和真实上游 smoke。
   付费 smoke 已获本任务授权；性能压测未获授权，不运行。

本阶段已通过 PostgreSQL/SQLite 全量测试、存量迁移与拒绝升级测试、Console 契约和
组件测试、33 项浏览器 E2E，以及两种后端的真实浏览器/Codex/Pi 系统验收。
已授权的真实上游 smoke 共 8 项通过，涵盖 Chat Completions、Responses HTTP/SSE/WS、
独立搜索及 Images 生成/编辑。前端全量测试使用 `--maxWorkers=2` 通过；
默认并发曾触发现有共享席位和模型价格测试的异步等待失败，未改动这些无关测试。

## 第二、三阶段：能力与路由联合切换

联合方案替代先保留旧渠道路由、再迁移候选的两次切换。新能力默认不自动启用、
授权或选路，但管理员可以显式授权、配置候选后使用，不再等待另一个发布阶段。
第一阶段的身份及认证语义保持不变。

### 唯一配置来源

| 实体 | 配置所有权 |
| --- | --- |
| 上游凭证 | 认证材料、目标范围及认证生命周期 |
| 上游接入 | 连接器、Base URL、默认代理及超时 |
| 逻辑渠道 | 凭证/接入绑定、管理组归属、总开关 |
| 渠道能力 | 操作、传输组合、模型目录、开关、变换、压缩和探测 |
| 管理组 | 组织关系、管理开关，不持有格式或连接器 |
| 路由候选 | 显式能力及上游模型，不引用历史渠道投影 |

普通渠道迁移为一个逻辑渠道及原有能力；Codex 的 Responses/Images 投影按稳定凭证身份
合并为逻辑渠道，分别产生 Responses、已有搜索、图片生成和图片编辑能力。
只接受连接器已经实现的操作/传输组合。普通 Connector 已支持显式开启的独立搜索，
不能误判为 Codex 独占。当前计划探测仍只支持普通 Chat Completions/Responses HTTP JSON，
不因新能力表出现而宣称已经实现 Codex、搜索或 Images 探测。

新实体是唯一写入和编译来源。撤销未发布草稿中的旧表全量反向同步触发器。
Console、导入、Token/额度刷新、模型发现、健康和删除路径分别通过所属资源的命令修改，
不能因旧渠道的任意 UPDATE 而覆盖整套新配置。数据库触发器只维护局部约束，不重建业务图。
旧 Console 写入接口在切换时移除或明确转换为新命令，不保留第二套独立可编辑状态。

### 按操作迁移路由

最终关系是：

```text
计价模型 → 客户端协议/操作规则 → 优先级层 → (capability_id, upstream_model, weight)
```

Images 原协议规则拆成生成、编辑两条操作规则；Responses 拆出其已支持的独立搜索候选。
各操作只接收原本支持该操作的候选，分别保留 tier、priority、weight、selection strategy
和 wire model，不能把不同操作混入同一个候选池或把权重翻倍。
同层只拒绝完全相同的能力/模型候选，跨层重复继续允许。
客户端模型、价格所属 `model_id` 和账单倍率语义不得因拆分而变化。

当前搜索也传递 wire model，不能丢掉别名、合并不同模型候选或移除目录限制。
只有以后实际实现无需模型的能力，才引入对应的显式无模型候选契约；
本次不使用空字符串或 `null` 把已有搜索偷偷变成无模型操作。

迁移规划使用 `(旧渠道 ID, 操作)` 映射生成最终候选。该索引仅在迁移时使用，
不能进入数据面的候选查找，也不成为旧路由的永久兼容层。无法无损映射时整批失败。
默认操作可保留原规则 UUID，派生操作使用确定性的新 UUID，并检查所有身份冲突。
空的停用草稿保持停用，不凭空创建候选。

### 授权与生命周期

迁移固定的是当时的能力目标集合，不是禁止授权表写入。创建 Key、明确调整授权和撤销
仍然必须有效。修改名称或额度等非授权字段不能重新展开组授权；新增能力不能扩大旧
Key/Policy 的权限。保留授权来源（组或渠道），同时检查当前归属，不用一张无来源集合
改变原有的组范围收窄语义。Policy 仍按现有自助授权规则使用，不自动改写已发 Key。

组聚合或 Codex 投影合并不能把 Responses 授权扩展成 Images 授权。
目标授权之外的 Key 格式权限、用户/Key 状态、传输开关、共享席位和准入检查仍独立执行。
拼车保护按稳定凭证覆盖所有能力及历史别名；不可计价的搜索仍不得通过拼车额度派发。

有效可用性分别取决于组、接入、逻辑渠道、凭证、能力和健康状态。
迁移各能力时读取它自己的旧组/渠道开关，不以 Responses 组的 enabled 覆盖 Images。
凭证的停用、额度及重新授权状态不折叠进能力配置开关。恢复凭证不得打开原来关闭的能力。
新父级开关的初值及旧开关下沉必须通过迁移前后逐操作可用集合等价测试。

凭证删除及范围收窄检查全部未删除逻辑渠道，包括停用、无路由及能力全停用的渠道。
修改共享接入的目标需校验所有引用凭证。引用检查与写入在同一个一致事务中完成，
不能让并发新增引用绕过删除或缩小范围的保护。

凭证、接入、绑定和能力分别拥有连接失效 revision，不能复用同一个绑定版本：
改绑接入/凭证、URL/网络策略变更、能力启停等推进对应版本；A → B → A 不能恢复旧版本。
WebSocket 对闲置、借出和归还连接都检查完整身份，失效 continuation 不换连接派发。
凭证状态、接入网络故障、能力失败及能力/模型失败按作用域隔离，不复制 provider 额度。

### 历史引用和旧表退役

路由、授权、Codex 身份和运行时查询全部切换后，才删除旧配置表及投影触发器。
迁移财务/日志外键引用到最小只读历史身份记录，保留原 UUID 和原金融事实，不重写金额、
结算收据或待处理任务。历史身份不能被编辑、授权或用于实时选路。
缺少操作证据的旧日志保留原身份，不猜测对应生成还是编辑能力。

Codex 直接关联公共凭证及自己的专属扩展，不再以渠道行作为 OAuth 身份的生命周期载体。
Token generation、额度窗口、拼车绑定、席位、WAL 和未决金额都沿用原凭证 UUID。
旧版本 spool/journal 解码及历史身份解析继续保留，不能把删除配置表等同于删除待重放数据。
