# 上游身份、渠道能力与路由目标

> 状态：当前。描述联合拓扑切换及后续迁移后的契约；旧渠道 CRUD、投影表和能力级授权
> 已退役。升级须停机和完整备份，不支持新旧 schema 混跑。

上游凭证回答“以谁的身份认证”，接入回答“连接到哪里”，逻辑渠道绑定二者，
能力声明具体操作，路由候选决定向哪个能力发送什么 wire model。
客户端 API Key 是独立的入站身份，不能与上游凭证混为一体。

## 实体与所有权

```text
上游凭证 ───┐
            ├─ 逻辑渠道 ── 渠道能力 ── 能力模型目录
上游接入 ───┘      │
                   └─ 管理组

客户端计价模型 ── profile ── 操作规则 ── priority 层
                                          └─ (能力, wire model, weight)
```

| 实体 | 唯一配置来源 |
| --- | --- |
| 上游凭证 | 稳定 UUID、连接器 ID、认证类型、静态认证材料/精确目标范围及生命周期 |
| Codex 扩展 | OAuth Token、账号、维护代理、账号模型目录、generation 与额度窗口 |
| 上游接入 | 连接器 ID、Base URL、代理与超时 |
| 逻辑渠道 | 接入/nullable 凭证绑定、管理组、总开关与 binding revision |
| 渠道能力 | 操作、模型目录、独立健康/开关、变换、压缩、探测、倍率及状态统计开关 |
| 管理组 | 组织关系与管理开关，不拥有格式、连接器或认证 |
| 路由候选 | 显式 capability、wire model、weight；由 tier 保存 priority 和 strategy |
| Key / Policy 授权 | 固定逻辑渠道与组/直接渠道来源，不是自动路由池 |

创建、导入或加载插件都不隐式创建其他实体，不自动授权、启用能力或添加候选。
管理组不是多对多标签，也不根据成员变化动态扩展路由。
没有第二层隐式凭证选路、自动协议降级、跨格式重试或万能中间协议。

## 凭证与目标范围

### 静态凭证

Bearer 或指定 Header 的 secret 只在凭证保存，不在渠道复制。
相同 secret 不代表同一业务身份，不按 secret 自动去重。
认证类型不可原地修改；改类型须新建凭证并显式改绑。

目标范围使用规范化后的完整 Base URL **精确匹配**，不是域名、子域或路径前缀：

- 仅 HTTP/HTTPS；拒绝 userinfo、query、fragment、首尾空白、控制字符和反斜杠。
- 使用同一个 Rust URL 规范化器处理保存、绑定、发现、编译和迁移。
- scheme/host 大小写及默认端口等价，尾部斜线按端点拼接语义移除。
- 不合并路径大小写、内部重复斜线、非末尾路径段或保留的百分号转义。
- 不用 SQL lower 或前缀比较代替规范化；迁移以原始地址作为规范化输入。

扩大范围是独立的管理员 ETag 修改并审计。
收窄范围必须验证所有未删除渠道，包括 disabled、auto-disabled、无候选或停用组中的绑定。
“临时不可用”不是解绑；共享接入的目标修改也必须验证其全部引用凭证。
检查与写入处于同一事务，不能让并发新增引用绕过保护。

### 管理与秘密

列表不返回 secret；详情按产品策略允许管理员查看静态 secret。
创建必须有合法认证材料及非空范围；更新省略 secret 表示保留，显式新值表示轮换，
不能静默清空。禁用阻止所有引用渠道的新请求，不删除路由；恢复不打开原来关闭的能力。

渠道写入显式 nullable credential_id，NULL 就是无认证，不造占位凭证。
严格反序列化拒绝旧内联认证字段；模型发现使用相同的凭证、范围和启用检查，
不提供任意密钥注入旁路。绑定还必须满足接入与凭证连接器 ID 一致。
创建、轮换、删除和改绑只记录脱敏审计，错误与 Debug 不输出材料。

普通凭证删除要求没有未删除渠道引用；清除 secret 并保留墓碑。
删除渠道不顺带删除共享凭证。Codex 修改、导入、导出和删除只走专属流程，
通用凭证接口不能改 Token 或伪装 OAuth 身份。

## 六种操作与显式路由

| 操作 | 传输与约束 |
| --- | --- |
| `chat_completion` | Chat Completions HTTP JSON/SSE |
| `responses` | Responses HTTP JSON/SSE |
| `responses-ws` | Responses WebSocket，独立选路、健康和日志操作 |
| `web_search` | 独立非流式搜索，仍使用候选 wire model 及目录门槛 |
| `images_generation` | 非流式 JSON 图片生成 |
| `images_edit` | 非流式 multipart 图片编辑 |

不持久化可配置 transports，不以独立布尔值生成未实现的操作/传输组合。
连接器声明实现上限，管理员只能收窄。已注册原生插件也不能扩大六操作集合。
Codex 对 HTTP 非流式 Responses 的拒绝仍有效，操作存在不代表连接器支持每种请求形态。

计价模型是客户端不可变身份；操作规则按 profile/operation 唯一。
启用规则必须有非空 tier，tier 的候选显式保存能力和上游别名。
同层仅拒绝完全相同的 capability/model；跨层重复允许。
相同模型名不证明操作兼容；搜索不能借“无需模型”改用空串/NULL。
图片生成和编辑分别建规则，HTTP 与 WS 也分别建规则；不混池、不翻倍权重。

定时探测目前仅支持 general 的 Chat Completions/Responses HTTP JSON。
wire test_model 和 test_pricing_model_id 成对设置，不能按 wire 字符串猜价格身份。
WS 不继承 HTTP 压缩和探测；能力表出现不代表 Codex、搜索或 Images 探测已实现。

## 逻辑渠道授权与能力删除

Key/Policy 的持久授权目标是**逻辑渠道**，不是能力：

1. 新增组选择在保存时展开为当时的固定渠道集合；新增组成员不自动获权。
2. 保留来源的名称、额度等元数据编辑不重新展开。组来源仍检查当前渠道归属。
3. 新增/删除授权来源是显式操作。自助选择与 Policy 的固定渠道集合相交；
   Policy 修改不自动改写已发 Key。
4. 已授权渠道的现有及未来能力共享授权；能力开关、候选、目录、模型、健康和准入仍独立检查。
5. 已删除或未知渠道不能使用；同名新 UUID 不继承旧授权。
6. allowed_api_formats 只作废弃 v1 兼容元数据，输入可省略，不是独立权限条件；
   活跃 Key 规范化为全部受支持格式。

0067 / SQLite 0007 按旧已授权能力所属渠道去重，而不是重新遍历当前组。
保留来源和最早授权时间；旧直接能力来源转为所属渠道直接来源，选择数组同步，
旧能力授权表退役。该迁移不改能力、路由、凭证、额度、金额事实、回执或 spool。

### 删除与依赖

删除能力使用详情 ETag，在同一控制面事务：

- 撤销其全部候选，清理空 tier，停用无候选规则；
- 保留其他候选的模型别名、权重、priority 和 strategy；
- 推进受影响规则 ETag，审计记录规则 ID 与停用结果；
- 写能力墓碑，保留渠道授权和金融历史。

这也适用于 Codex 能力。Console 明确提示自动解绑/停用，并失效能力与规则缓存。
逻辑渠道必须先退役能力，管理组必须先清空渠道；仍被未删除渠道引用的接入/凭证不能删。
不再使用旧组/渠道级联删除和影响确认 token。
模型墓碑删除另会撤销其候选及探测引用，避免永久占用能力，详见[软删除](soft-deletion.md)。

## 统一凭证与逻辑渠道

`routing_groups → upstream_channels → upstream_credentials` 是所有连接器的共同组织模型。
凭证不属于组/pool；导入、重新授权、启停或改名不创建或修改渠道拓扑。

- credential.connector_kind 是显式、不可变连接器 ID，与认证材料类型独立。
  静态凭证默认 general，也可归属已注册原生插件；codex_oauth 只允许 codex。
- OAuth 公共身份 UUID 保持稳定，Token 不复制到通用身份记录。
  专属表历史 channel_id 名称表示凭证 ID，不是当前逻辑渠道外键。
- OAuth 扩展拥有维护代理和账号目录；维护状态不覆盖渠道接入、能力目录或开关。
  删除先解除全部未删除渠道引用，再走专属 Token 擦除和墓碑事务。
- 额度窗口按凭证 UUID 延续。用户可见性经用户组授权的渠道组所引用凭证限定，并按账号去重，
  不是重新引入 pool 所属。
- SQLite 未决 refresh/quota-reset intent 在迁移、导入和关闭/重开时保持原恢复边界，
  不能因身份/表名变化清除未知兑换，见[SQLite Codex](sqlite-codex.md)。
- 原生连接器注册表属于进程运行时实例。启动和控制面提交前检查所有未删除接入、凭证、
  能力，包括停用与未绑定草稿；未注册 ID、未声明操作或缺所需命令均拒绝发布。
  插件安装不自动启用，详见[插件设计](connector-plugins.md)。

请求凭证归属与当前绑定分开保存：
journal v8 捕获选中快照的 UUID 或明确无认证；
旧 v2–7 为未知，查询才用冻结渠道注册表回退。
归属侧表与事实同事务，冲突不覆盖；后续改绑不移动已完成或在途请求费用。

## 运行时与连接失效

完整控制面记录一次性编译为不可变快照，数据面不逐请求查库。
非法引用、连接器/认证类型冲突、越界目标或禁止认证 Header 使候选编译失败，
回滚整个 mutation；不能发布认证为空的替代配置。
禁用是合法配置状态，选路排除即可。

请求保持取得的身份视图；轮换不承诺撤回已发出的请求。
Codex Token 继续通过独立凭证快照和刷新互斥维护。

WebSocket 池身份包含凭证 UUID/revision、接入 revision、渠道 binding revision、
能力 revision 及既有 session/Key/候选/网络/最终 Header 维度。
轮换、启停、范围/网络/能力变更推进对应版本，不以名称或 updated_at 精度代替。
A → 空/B → A 不能恢复旧连接，引用同一凭证的不同渠道不能因此混池。

闲置、借出和归还连接均验证有效性，仅清空闲池不够。
失效 continuation 返回 404 previous_response_not_found，不换新连接派发；
无 previous-response 的新请求可以重新连接。
凭证状态、接入故障、能力失败及能力/模型失败按作用域隔离，不复制提供方 quota。

入站/出站白名单、插件隐私、用户权限、Images 不可重试和 WS 连接局部状态均维持，
该拓扑不引入协议转换或绕过准入。

## 历史引用与升级

运行时仓储只读新拓扑。最小只读 identity registry 保留旧 UUID/名称及 canonical 身份，
金融事实、日志与旧 spool 可继续引用；注册表不能被编辑、授权或用于实时选路。
旧日志操作证据不足时保留原身份，不猜图片生成还是编辑，不改金额或回执。

| PG / SQLite | 转换与不可省略的约束 |
| --- | --- |
| 0064 / 0004 | 每个旧有认证渠道建立独立凭证，即使 secret 相同也不合并；无认证保持 NULL；Codex 保留 credential UUID |
| 0065 / 0005 | 事务内转存接入/逻辑渠道/能力/操作规则，迁移历史外键并删除旧表；保留旧各操作开关，不以 Responses enabled 覆盖 Images |
| 0066 / 0006 | 拆 HTTP/WS 六操作，删除 transports；旧 HTTP JSON-only/SSE-only 合并为两者，不自动打开 WS |
| 0067 / 0007 | 固定能力授权投影为逻辑渠道授权，保留来源，不按当前组重新扩权 |
| 0068 / 0008 | 移除凭证/flow 的 pool 归属；旧组绑定 flow 失效，保留账号、额度、未知维护 intent，不合并历史重复账号 |
| 0069 / 0009 | 追加不可变请求凭证归属；旧未知只读回退，明确无认证不回退 |
| 0070 / 0010 | 凭证连接器列改显式 ID，接入改有界 ID；保留 UUID/revision/时间戳和保护 |
| 0071 / 0011 | 插件生命周期和独立设置 |
| 0072 / 0012 | 先隔离旧拼车受保护身份/别名的渠道，再移除拼车专属表列；普通账本和额度历史不被清零 |

### 联合迁移的规划规则

`capability_cutover/` 使用旧渠道/操作映射规划，迁移后不成为数据面兼容层。
默认操作可保留原规则 UUID，派生操作使用确定性 UUID；冲突或无法无损映射则整批失败。
停用空草稿不造候选，旧暂时断连配置不静默丢弃。

六操作拆分中，HTTP-only/WS-only 保留原能力 ID；两者都有时原 ID 留给 HTTP，
WS 派生独立 ID。规则/tier 只投影一次时保留 ID，双投影原 ID 留给 HTTP；
无该操作候选的层不迁移。复制别名、权重、priority、strategy、开关、健康、变换、
倍率和时间戳；WS 清空压缩/探测。规划包含停用及墓碑，拒绝跨操作候选、
派生 ID 碰撞和无目标授权。旧组来源保留，即使移组后已不生效，也不按当前组织关系重授。
历史 0065/0005 使用冻结 DTO，最终运行时校验在六操作完成后进行。

升级预检包含非法 URL/认证的停用草稿，只报告资源 ID 和错误类别，不输出原 URL/secret。
管理员须在旧 schema 修复或删除后重试；不能丢材料、放宽范围或假定无认证。
迁移在既有原子批次完成，失败连历史记录一起回滚，不新增 PG enum 提交屏障。
SQLite 表重建仅在专属连接 BEGIN 前关闭 FK，提交前完整 foreign_key_check，
连接随后丢弃；回填元数据时暂撤 fence 也必须保留 intent 并恢复保护。

### 发布与回退

停止全部旧流量与写者，使用实际数据库和全部 spool 的成对备份，
验证存量升级、完整候选编译和恢复后才接流量。不能只用空库验证替代存量迁移。
提交后优先 forward-fix；恢复必须是同一时点的库、全部本地证据和匹配二进制，
并核对恢复点后上游使用，不能只回滚程序或数据库。
拼车移除的人工重新授权见[运维升级](../user/operations.md#codex-拼车移除升级)。

## 验证与设计背景

### 验证任务

- 双后端新建/存量升级、重复启动、非法停用草稿、表重建失败和原子回滚。
- Bearer/Header/无认证、共享凭证轮换、单渠道改绑、范围收窄、禁止 Header、在用删除。
- ETag、权限、旧字段严格拒绝、秘密列表脱敏与审计不泄密。
- 固定渠道来源、新增组成员不扩权、已授权渠道新增能力可用、Policy 自助交集及墓碑保护。
- 六操作路由隔离、HTTP/WS 不自动扩权、模型别名/权重保留、删除候选清理与模型墓碑。
- WebSocket 闲置/借出/归还及 A → B → A 版本失效，continuation 不换连接重发。
- Codex 导入/刷新/删除、OAuth 所有权、窗口费用、SQLite 未决 intent 和普通写者继续推进。
- 请求时凭证归属、明确无认证/旧未知、改绑后的费用与旧 journal 重放。
- Console API/generated types、组件/浏览器和真实 PostgreSQL/SQLite 系统 E2E。
  转发变更按授权运行真实上游 smoke；不自动运行性能负载。

代码入口：`src/persistence/{upstream_credentials,upstream_topology,capability_cutover}/`、
`tests/codex_capability_integration.rs`、双后端控制面/计量契约和 Console spec。
历史 schema inventory 与当前 inventory 分开，不能覆盖历史夹具来让升级测试通过。

### 设计演进

原渠道混合地址、认证、格式和目录，Codex 使用 Responses/Images 自动投影。
独立凭证先解决共享认证，联合拓扑切换随后把操作与候选迁移到唯一配置来源。
之后六操作、逻辑渠道授权和无 pool 凭证分别替代了早期设计，本文不再把旧阶段写成现行规则。

既往交付记录包含双后端 workspace/Clippy、Console、浏览器、系统 E2E 和已授权
8 项真实上游 smoke 通过；这些是对应历史版本的验收，不是本页维护时重新运行的结果，
也不保证当前上游可用。Codex 非流式 Responses 的 smoke 验证预期拒绝，
并非证明其支持非流式生成。没有性能压测结论。
