# 原生连接器插件

> 状态：当前实现。本轮实现验收已通过，尚未合并或发布。

## 范围与仓库

网关维护授权、准入、路由、传输、存储和财务，连接器维护服务商协议。
`general` 保留为内置实现；`codex` 由独立公开仓库
[ai-gateway-connectors](https://github.com/oai404iao/ai-gateway-connectors)
构建为原生动态库。管理员单独安装插件，网关镜像和发行包不捆绑 Codex，也不提供内置回退。

主仓库拥有 `crates/connector-sdk`、C ABI、加载器和契约测试。
插件仓库只依赖已固定版本的公开 SDK，不引用主仓库内部 Rust 模块或数据库。
第一版支持 Linux；不同架构、libc 和 ABI 的制品不可混用。
SDK 源提交以 `connector-sdk-v0.1.0` 注释标签保留；插件依赖仍固定完整提交 SHA，
不依赖可移动分支。公共命令契约与可运行示例见
[SDK 命令](../../crates/connector-sdk/docs/commands.md)。

## 不可下放的职责

- 公共六操作、客户端格式、API Key 与 Console 权限。
- 逻辑渠道授权、候选/模型选择、亲和性及每次请求的凭证归属。
- Fast 过滤、入站白名单、禁止 Header、Codex 隐私归一化与最终出站检查。
- 请求大小、multipart 临时存储、背压、取消、超时、代理、TLS、压缩及连接复用。
- 持久日志 intent、usage 完整性、价格、结算、拼车金额预留、WAL 和恢复。
- 凭证事务、目标范围、generation、维护并发控制和外部操作 intent。

插件不能另选渠道、模型或凭证，不能扩大目标范围、授权或重试条件，
不能注册公共 HTTP 路由、执行 SQL、修改余额或加载前端 JavaScript。
这些是可信代码接口契约，不是原生代码沙箱。

## 身份和配置

连接器 ID、认证材料类型、公共操作分别建模。`general`、`codex` 保留原标识；
外部 ID 必须是长度受限的 ASCII 标识。静态 Bearer/Header 凭证可以明确属于相应连接器，
但 `codex_oauth` 只能属于 `codex`，不能通过伪造插件身份绕过金融保护。

进程 TOML 的 `[[plugins]]` 指定 ID、绝对动态库路径和文件 SHA-256。
不从环境变量、工作目录扫描、数据库或远程 URL 隐式寻找生产插件。
管理凭证、渠道、能力和路由继续通过数据库完整快照原子发布。
插件二进制集合固定到进程生命周期，配置修改不能替换动态库。

加载成功仅代表实现存在，不创建接入、渠道、能力、路由或授权。
新增插件操作也不自动开启能力。保持当前授权语义：显式新增的渠道能力共享该逻辑渠道授权，
不是恢复早期的固定能力授权。

启动及控制面发布校验实际插件和操作可用性；缺失插件不得降级为 `general`。
未删除的接入与凭证（包括未绑定或停用草稿）仍要求插件存在，避免保存无法验证的配置。
历史墓碑不是活动派发对象；历史日志和金额查询不依赖插件仍然存在。

## ABI 与执行模型

单一导出符号 `ai_gateway_connector_entry_v1` 返回版本化 C 函数表。
结构只包含明确布局的整数、字节切片、函数指针和不透明所有权。
不传递 Rust enum/trait、`String`、`Vec`、`Future`、Tokio 对象或数据库句柄。
接口结构大小、主次版本、保留字段、错误和内存释放规则由 SDK 规定。

ABI 调用分开传递命令、JSON 控制元数据和原始 body 字节，避免为了跨边界编码大 body。
输出同样分为元数据与原始字节；内存由分配方的释放函数释放。
输入借用仅在调用期间有效，禁止跨调用保存借用指针。
插件导出包装层捕获可捕获 panic，不允许异常跨 C ABI 展开。

插件回调是同步、有界、非阻塞的纯协议步骤。宿主负责所有异步 I/O：

1. 插件将上下文转换为请求或流处理计划。
2. 宿主校验计划、执行网络/磁盘操作。
3. 插件解释已完成步骤的结果。
4. 宿主决定继续、完成、记录失败或保留不确定状态。

第一版不开放插件线程、定时器、运行时和任意 Host RPC。纯步骤由宿主现有状态机串联；
无需向 C ABI 暴露 Rust Future。后续增加通用长生命周期状态机须单独版本化，
不能把当前的无状态命令悄悄改为持有输入 buffer 的有状态调用。

## 数据面

正常顺序保持：

```text
认证/入站策略/Fast 过滤
  → 授权/准入/选路/日志 intent/必要的金额预留
  → 模型映射/受限 Transform
  → 插件协议适配
  → 宿主出站策略/隐私规范化/Header 清理/认证/最终 guard
  → 宿主 HTTP 或 WebSocket
  → usage/终态日志/结算
```

操作内部的既有安全次序以请求策略契约为准。插件不得恢复已过滤 `service_tier`、
工作区路径、原始安装指纹或 forwarding Header。
目标与认证 Header 都需宿主复核；不能把插件返回的完整 URL 当作已授权目标。
保持请求未修改时原字节透传。

### Images

插件处理字段兼容、图片数量限制、provider JSON 结构和 MIME 规则。
宿主继续使用 `ReplayableRequestBody` 的内存/匿名临时文件边界，顺序读写和增量 base64；
插件返回有界字面量/图片片段计划，不获取临时文件路径，不接收整幅图片的 JSON 编码副本。
图片编辑不开放 JSON Transform，也不改变不可自动重试规则。
`replay_multipart` 保留图片和 mask、原始 Content-Type（包括带引号 boundary），或仅按宿主
已确定的模型/忽略字段规则重建。`json_base64` 使用有界模板，明确拒绝 mask 和未表示的二进制
字段，不能静默丢失输入。宿主确保最终 Content-Type 与实际 body 模式一致。

### WebSocket

socket、握手和池属于宿主。每次 create 独立鉴权、准入、记录，
保持一个请求独占连接和精确 continuation 命中。
池显式隔离连接器 ID，凭证、绑定、能力及网络 revision 仍保留。
插件制品摘要在进程内固定，升级需要重启并清空整个池，因此不存在同进程混用两版库的情况。
插件不能把池 miss 转成新账号派发，不能吞掉状态恢复控制错误。

### 重试和计量

重试必须同时满足公共操作、管理员配置、插件约束和当前派发状态。
任何响应头/字节送达客户端后不得重试；Codex 和 Images 原有限制不变。
插件错误映射到宿主错误分类，不直接控制健康、HTTP 状态或账单。
标准 usage 仍由宿主解析，未知 usage 不伪造为零，财务事实不依赖 provider 扩展 JSON。

## OAuth、配额与控制面

插件拥有 OAuth endpoint、授权 URL、Token/配额/模型请求构造、结果解析和账号 claim 解释。
宿主拥有 PKCE/state 防重放、授权流程寿命、网络执行、凭证范围、响应上限、持久化及审计。
数据面 endpoint 与维护 endpoint 的允许范围分离，重定向不得泄露认证材料。

现有 Codex 专属持久化结构允许保留：外置协议不要求把所有表重写为通用 KV。
Token refresh 的互斥、数据库锁、generation，SQLite 持久外部操作 intent，
配额兑换的不确定结果和金融窗口均由宿主维护，插件无权清除。
凭证 UUID、账号金融绑定、渠道、席位、窗口和历史费用原值保留。

Console 继续由宿主提供管理 API 和页面。Codex 页面可以继续作为宿主控制面适配壳，
但协议解析和上游维护请求必须进入插件。无插件时，纯存储/历史查看不应隐式执行 provider 操作。

## 加载和故障模型

插件是经过审查的可信原生代码，能够破坏整个宿主进程。
SHA 校验用于绑定管理员批准的制品，不是代码安全证明；发布签名、摘要也不能提供沙箱。
死循环、段错误、内存破坏和 abort 无法通过错误码或 Tokio timeout 安全恢复。
不承诺“超时后强杀插件线程仍继续服务”。

在加载前校验文件摘要和配置，在加载后检查 ABI、ID、manifest 和必需命令。
防止摘要校验与加载使用不同文件；路径和目录不得成为非授权用户可替换制品的入口。
显式配置加载失败导致启动失败，不忽略错误。
库必须覆盖所有函数指针及返回内存的生命周期；第一版不执行运行中卸载。

插件升级采用停止、替换经验证制品和摘要、重新启动。回滚同时检查状态 schema 兼容性，
不能直接把升级后的凭证状态交给不理解它的旧插件。

## 交付与验证

插件仓库独立发布版本和平台制品，归档包含库、manifest、校验和和许可证材料；
SDK 使用不可变版本/提交。主项目 CI 使用固定插件测试版本，不在生产构建时联网安装。

验收包含：

- ABI 版本/布局、错误输出、内存释放、摘要错误、ID 冲突和缺少命令。
- `general` 独立运行、外部插件无内置回退、缺失插件 fail closed。
- Codex OAuth、刷新、配额、兑换、导入、模型发现的行为等价。
- Responses HTTP/SSE/WS、搜索、Images 生成/编辑和取消/断流。
- 凭证目标、Fast/隐私/Header 策略、不可重试和 WS continuation 负例。
- PostgreSQL/SQLite 存量升级、金融恢复、旧 journal 和双后端系统 E2E。
- Console/OpenAPI、前端检查、插件独立 CI 和发行包校验。
- 已获授权的真实上游 smoke。性能压测不在本任务范围。

具体执行结果在完成报告记录，设计文档不代替未执行的验收。

本次本地验收通过双后端 Rust 回归、无新增警告的 Clippy、230 项 Console 组件测试、
40 项浏览器测试、两种后端的真实浏览器/CLI 系统 E2E，以及 Docker canonical entrypoint
以 UID 10001 加载外部插件。外部插件 15 项测试、发行包校验和初始双架构 CI 通过。
此前付费 smoke 的 Responses HTTP/WS 和搜索因已停用模型未通过。
使用更新后的受保护 smoke 配置重新执行完整脚本，8 项全部通过、无跳过：
Chat 非流式/SSE、Responses SSE/WebSocket/非流式边界、独立搜索及 Images 生成/编辑。
本次复测未修改现有上游实例的渠道或模型配置，也未运行性能压测。
