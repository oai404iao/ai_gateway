# Codex 拼车实现

> 状态：当前。单实例固定席位金额准入；操作说明见[用户指南](../user/codex-sharing.md)。

## 所有权和源文件

- `migrations/0054_codex_sharing.sql`：车队、稳定席位、不可变绑定/上游身份、
  单个数据库账本 ID。配置金额为 `numeric(20,8)`，不是余额结算实体。
- `migrations/0055_codex_sharing_only_groups.sql`：默认关闭的 Codex 整池访问模式，同步配对组，
  不修改已有拼车、窗口或账本数据。
- `src/domain/codex_sharing.rs`：输入验证、用户组成员与受保护投影注册表。
- `src/persistence/codex_sharing.rs`：管理员配置、所有权条件 SQL、完整窗口加载和批量对账。
- `src/codex_sharing.rs`：独立单写线程、金额状态、预占 RAII、增量 WAL 与检查点。
- `src/application/proxy.rs` 的 `CompletionGuard` 与 `proxy/websocket.rs`：
  发送前预占、完成时按现有账单结算；WebSocket 每条逻辑请求独立执行。
- `src/main.rs`：进程开关、数据库连接锁、后台对账和关停顺序。
- `src/http/console/codex_sharing.rs`、OpenAPI 与 `web/console/src/features/codex-sharing/`：
  管理和本人视图。

## 配置与选路

`[codex_sharing].enabled` 只控制进程账本，默认 false。配置实体和绑定始终加载进完整运行时
快照；关闭进程开关不能放开数据库中已经保留的受保护凭证。
`ControlPlaneCoordinator` 在发布快照时同步账本元数据。数据面不逐请求访问 PostgreSQL。

每个用户组、逻辑凭证、可识别的 `(account_id?, provider_user_id)` 只能绑定一个车队。
同一身份跨 pool 导入的其他投影也受到保护；拼车请求只使用原绑定的两个投影。
注册表按目标渠道而不是按用户整体实施限制。普通渠道保留既有授权和计费，完成回调
仅在 `for_channel` 找到实际绑定时预占/结算拼车金额；普通调用不依赖拼车运行时健康。
注册表只收窄既有 API Key 授权交集，不创建格式、模型或 Images 权限。
暂停与空席仍保留保护；绑定和既有席位编号不可修改或删除。

`channel_groups.sharing_only` 仅对 Codex 合法，默认 false、PUT 省略保留。数据库触发器
将同池两个格式组同步；不会启用 Images。完整快照包含专用池及可识别身份副本的保护 ID，
因此未绑定凭证也无法走普通路径，探测任务也不消费这些凭证。开关关闭不会解除已有绑定。
已选中的拼车凭证在准备/准入失败后不改走普通渠道；初始目标仍服从原模型路由，需固定拼车
用途的模型应使用专用规则。发布路由模式不修改窗口元数据和账本，保留金额与预占。

成员关系以用户当前用户组为准。历史席位引用可以保留，但新增/替换的成员必须是组内活跃用户。
保护渠道的计划探测会被跳过。搜索响应不能计价，因此共享请求的该操作在 dispatch 前拒绝。
该限制不改变普通路径（包括拼车成员的普通调用）的独立搜索协议，也不修改请求白名单。

## 金额与窗口

每窗口冻结 `floor(total / seats, 8 decimal places)`。独立维护席位使用量与用户使用量；
准入同时检查两者以及整车上限，防止换座或换人重复领取。固定预占同时写入全部有效窗口。
有效剩余取用户/席位剩余的较小值；展示的“已用/继承”和有效预占不等同于本人的原始账单。
结算使用现有 `RequestBilling.cost_amount`，包含原定价与倍率，不重新计算历史价格。
未知用量、负数/溢出及存储错误不能被转换为免费成功。

窗口加载要求当前凭证报告的所有窗口都具有匹配的历史行、重置时间、百分比、长度和
观测版本。不能把新鲜的 `quota_checked_at` 套在旧窗口行上，也不能只加载主窗口后绕过
仍然存在的次窗口。180 秒新鲜度和到期检查在本地执行。

通常以 `codex_quota_window_periods.id` 作为金额 epoch。整数 `0%` 的上游历史 ID
可能不变而重置时间持续滑动：在首次准入或出现待生效分配变更时持久化固定边界；
后者保证全空车也能在下一窗口完成扩座。边界后新鲜的 `0%` 观测
才允许切换到新的本地 UUID epoch。`source period -> effective epoch` 映射也持久化。
尚未锚定的零窗口可继续校准预计边界，不能通过反复刷新已使用窗口获得预算。
这是一种明确的金额周期推断，而不是对上游真实小数使用量的恢复。

窗口只在预占时选择，跨窗完成仍写旧 epoch。主、次窗口不是可以相加的两份账单；
扩座/调预算独立等待各窗口切换。初始化不追补创建前的请求，也不发放错过窗口的结转额度。
不可证明请求最大费用，因此是软金额门禁；不要绕过 Codex 的 `max_output_tokens`
ignore 策略来假装实现硬费用上限。

## 耐久写入顺序

1. 单写线程验证席位、完整窗口、流控、用户/席位/整车可用金额。
2. 在内存构造预占变更，追加带序列号和 SHA-256 校验和的 WAL frame。
3. WAL fsync 成功后回复调用者，之后才允许发送上游。
4. 完成回调追加实际结算或未知用量状态；请求 UUID 在 pending 集合中只移除一次。
5. 每累计约 4 MiB WAL，将完整状态写临时文件、fsync、rename 并 fsync 目录，
   **之后**才能截断并 fsync WAL。

热路径写的是变更而不是整个历史快照。重启时重放检查点之后的连续序列；检查点已包含的
旧 frame 跳过，完整 frame 校验失败或序列缺口拒绝恢复。未完成的最后一帧按未确认追加
处理；已经完整编码的尾帧可以保守重放。不能用这些恢复规则容忍回滚或丢失已 fsync 的数据。
原检查点缺失而 WAL 尚在时拒绝创建新账本。
已有检查点而 WAL 缺失也拒绝启动，不能创建空日志来代替丢失的金额变更。

重放后所有 pending 都标为 uncertain。后台最多按 1,000 个 UUID 查询已有请求日志的
`cost_amount`，再发幂等结算命令。该查询不是逐请求 SQL，也不引入第二次余额结算。
无法确认的旧请求只冻结与其仍活跃窗口相关的用户/席位；过期窗口不阻碍下一窗口。
维护时保留当前窗口、仍在途引用和最近 90 天的状态，清除更早且无活跃依赖的历史。

队列有界，发送/等待回复各有 5 秒超时；队列/持久化异常使运行时进入不可用状态，
结算使用单独的有界优先队列，不能被普通查询队列占满而丢弃。
不能默默丢弃结算后继续发额度。单文件 64 MiB 上限也是 fail-closed 边界。
金额状态不包含 Prompt、响应正文、上传图像或 OAuth Secret。

## 单实例与恢复限制

文件锁排除同目录多写者；独占数据库 advisory lock 和持久化 ledger UUID 拒绝不同账本的
第二个进程。持锁连接由后台保活，对账与配置热加载都不能替换或释放这份所有权。
关停先排空转发和日志，再刷新金额命令，最后释放连接。

这些措施不是网络分区下的分布式 fencing，也不是跨机器金额同步。禁止复制账本后并行
运行、混跑不支持拼车的旧版本或在线任意组合恢复数据库与账本。支持的备份方式是停机后
一致性保存数据库和整个 spool，再以同一个单实例恢复。

## 契约和验证

Console 管理端使用管理员角色与 ETag/If-Match；本人查询在 SQL 中绑定认证 user ID，
忽略客户端伪造的 user ID，不返回其他成员或上游凭证身份。
响应定义只维护在 [OpenAPI](../openapi/console-v1.yaml)，前端类型必须生成。

主要确定性覆盖：

- `src/codex_sharing.rs`：双窗、幂等、固定席位、未知使用、重启、零窗口漂移、
  WAL torn tail、检查点重叠、序列/校验损坏、文件锁及流控。
- `tests/control_plane_integration.rs`：跨 API Key HTTP/SSE 与逐条 WebSocket 扣额，
  Images 权限和共用金额、搜索拒绝、凭证约束、配置刷新和缺失窗口。
- `tests/console_spec_integration.rs`：配置/本人视图、角色、隐私、ETag 与无运行时拒绝启用。
- Console 组件与 Playwright：金额页面、固定 Select 默认值、保存和冲突重载。

运行普通 Rust/Console/浏览器门禁，并按[真实上游测试说明](real-upstream-smoke.md)
执行已授权的付费回归；性能压测仍必须另行授权。
