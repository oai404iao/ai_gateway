# MVP 3 后端任务清单

目标：在已完成的 PostgreSQL 控制面、不可变运行时快照和单次代理转发之上，实现受限请求/响应变换与可复用的上游客户端管理。MVP 3 使管理员能够安全地配置模板、渠道覆盖和出口代理，同时保持流式响应、格式隔离和不重试约束。

## 范围与边界

- 本版本实现 `config_templates`、`channels.override_document`、`proxies` 与渠道超时字段当前已存在的数据库模型；它们由控制面编译进不可变快照，数据面不查询数据库。
- 只支持 OpenAI Chat Completions 与 Responses；两种格式的解析、变换验证和 SSE 事件处理路径必须分离，禁止在格式之间回退或转换。
- 变换固定顺序：模板默认值 -> 渠道覆盖 -> 上游认证。上游认证始终最后执行，变换不得改写认证或受保护/hop-by-hop 请求头。
- 透明路径优先：未启用任何 body 变换时保留原始请求 bytes；上游流响应默认逐块转发，禁止为普通代理响应整流缓冲。
- 仍然只允许单次上游尝试。响应头或任一响应字节发送后，不得重试、切换渠道或更换代理。
- 管理面普通读取和审计记录不得包含代理密码、上游密钥、Authorization/Cookie 等敏感字段；敏感字段只可通过明确、审计过的后续凭据操作处理。

## 执行约定

- 每个阶段开始前，将阶段目标和可验证子任务写入本文件；只有全部子任务、测试和提交完成后才开始下一阶段。
- 每完成一项就在本文件勾选；提交记录必须包含该阶段的实现、测试和清单更新。
- 阶段间保留既有测试，不以跳过或弱化既有行为换取进度。
- 配置写入必须通过现有 `ControlPlaneCoordinator`：同一事务内写入、读取完整候选控制面、编译、记录 allowlist 脱敏审计，然后提交并发布快照。

## 阶段 1：模板、代理与渠道策略快照

阶段目标：将模板、出口代理和渠道覆盖/超时从数据库完整编译为可安全发布的运行时快照，使现有渠道能够在不改变默认透明代理行为的前提下引用它们。

阶段状态：已完成

实现拆分：

- 控制面：补全代理和模板的事务读取、受控管理表示、乐观并发写入与脱敏审计。
- 编译快照：将代理、模板和渠道网络/变换策略编译为不可变强类型对象，并在发布前完成引用与安全校验。
- 管理 HTTP：提供代理与配置模板的列表、读取、创建、全量更新端点。
- 验证：用单元和隔离 PostgreSQL 集成测试覆盖失败回滚、脱敏与即时快照发布。

阶段设计记录：

- 变换文档采用封闭的 `version: 1` JSON DSL；非空文档必须指定匹配渠道的 `api_format`。编译结果为格式分离的不可变计划，模板层与渠道覆盖层按固定顺序组合。
- DSL 仅允许请求/响应头 `set`、`remove`、`rename` 及 JSON `add`、`replace`、`remove`；拒绝未知字段、脚本、表达式、重复/冲突目标和受保护头部。
- 代理仅接受 `http`、`https`、`socks4`、`socks5` URL；渠道只可引用启用的代理、模板。渠道显式超时必须为正数。
- 普通管理表示和审计绝不包含代理密码、模板文档或渠道覆盖文档；只记录 allowlist 元数据。

### 阶段 1 执行任务

- [x] 1.1 定义 `ProxyRecord`、`ConfigTemplateRecord` 及其仓储读取模型；将它们加入一致性控制面读取与测试种子。
- [x] 1.2 定义已编译的代理、模板和渠道上游策略领域类型；所有 URL、超时、JSON 文档和引用以强类型方式表达。
- [x] 1.3 校验代理 URL/协议、`no_proxy_hosts`、渠道代理/模板引用、渠道超时正值与 API 格式兼容性；错误不得输出凭据。
- [x] 1.4 编译 `config_templates.document` 与 `channels.override_document` 为受限变换计划，拒绝未知字段、重复或冲突操作和受保护头部操作。
- [x] 1.5 将模板、代理与渠道策略纳入 `CompiledRuntimeConfig`，保持旧快照隔离和失败重载回退。
- [x] 1.6 扩展管理面提供代理和模板的列表、读取、创建、全量更新及乐观并发；普通表示和审计只输出 allowlist 非敏感字段。
- [x] 1.7 添加隔离 PostgreSQL 测试，覆盖跨表引用、无效超时/代理、编译失败回滚、审计脱敏和立即快照发布。

## 阶段 2：受限请求变换

阶段目标：在请求发送至上游前执行可预测、可验证的头部和 JSON 变换，同时保留无变换请求的原始 body bytes 与受保护头部。

### 阶段 2 执行任务

- [ ] 2.1 定义受限 DSL：请求头 `set`、`remove`、`rename` 及 JSON Pointer/Patch body 操作；所有操作使用显式 AST，不接受自由脚本或表达式执行。
- [ ] 2.2 实现编译期文档结构、指针、Patch 类型和格式验证；禁改 `Host`、`Content-Length`、`Connection`、`Transfer-Encoding`、`Authorization`、`Proxy-Authorization` 及其他 hop-by-hop 头。
- [ ] 2.3 在代理 use case 中按模板默认值、渠道覆盖、上游认证的固定顺序应用请求变换；模型 alias 仍遵循既有格式隔离规则。
- [ ] 2.4 当未启用 JSON body 变换时直接转发原始 bytes；仅在启用 JSON 变换时解析并重新序列化 body，维持当前大小限制和错误映射。
- [ ] 2.5 将无效 JSON、无法应用的受限 Patch 和受保护头部操作映射为安全的客户端/管理面错误，不接触上游且不泄露文档或凭据。
- [ ] 2.6 添加单元与代理集成测试，覆盖顺序、头部保护、无变换字节保持、两种格式隔离、Patch 失败与上游零接触。
- [ ] 2.7 运行格式化、静态检查和全部测试，并提交阶段 2。

## 阶段 3：响应与 SSE 事件变换

阶段目标：在不缓冲整个上游响应的前提下，支持受限响应头变换和逐 SSE 事件的 JSON 变换，并保留既有流空闲超时、取消和单次尝试语义。

### 阶段 3 执行任务

- [ ] 3.1 定义独立于请求变换的响应头和 SSE `data:` JSON 变换计划；明确每个 API 格式允许的事件类型与不可变字段。
- [ ] 3.2 在发送响应头前应用允许的响应头变换并清理 hop-by-hop 头；响应头发送后不得重试或切换渠道。
- [ ] 3.3 实现增量 SSE 帧解析器：按事件边界处理 `data:` 载荷，支持跨 chunk 边界，未匹配或不含 JSON 的事件原样传递。
- [ ] 3.4 对启用的 SSE JSON 事件执行已编译 Patch；单事件失败以协议安全方式终止流并记录终态，不缓冲后续事件或整条流。
- [ ] 3.5 保持客户端取消向上游传播、流空闲超时和渠道/准入租约释放；变换层不得创建后台泵或吞掉 body 错误。
- [ ] 3.6 添加跨 chunk、首事件低延迟、非 SSE 透明转发、事件 Patch 失败、取消和空闲超时集成测试。
- [ ] 3.7 运行格式化、静态检查和全部测试，并提交阶段 3。

## 阶段 4：上游客户端注册表与出口代理

阶段目标：按出口代理、TLS 与有效超时策略复用 reqwest 客户端，并将渠道级网络策略接入单次转发路径。

### 阶段 4 执行任务

- [ ] 4.1 定义可哈希的 `UpstreamClientKey`，由已编译的代理、TLS 和连接超时策略构成；禁止以每个请求新建 `reqwest::Client`。
- [ ] 4.2 实现进程级 `UpstreamClientRegistry`，惰性构建并复用 HTTP/SOCKS 出口客户端；代理凭据不得进入 `Debug`、追踪、错误或普通管理响应。
- [ ] 4.3 实现渠道显式超时与全局 TOML 默认值的确定性合并；连接、响应头、流空闲超时的所有权保持清晰且可测试。
- [ ] 4.4 将注册表接入代理 use case，使每个选中渠道使用对应客户端与有效超时，同时保持现有被动健康和单次尝试规则。
- [ ] 4.5 实现 `no_proxy_hosts` 匹配并验证代理不可用、连接超时和响应头超时的安全错误映射；不得静默直连以绕过已配置代理。
- [ ] 4.6 添加本地 HTTP 代理/直连选择、客户端复用、超时覆盖、代理失败、取消和跨快照策略替换的集成测试。
- [ ] 4.7 运行格式化、静态检查和全部测试，并提交阶段 4。
